# 取数规范（单一真源）

本文件是**工具路由、查询写法、调用纪律、来源与置信度判定、口径降级、Fallback** 的唯一真源。
`SKILL.md` 只引用本文件，不重复展开规则。

---

## 1. 工具路由表（用户样例写法 → 真实契约）

> 常见的「用户样例查询 YAML」直接照抄会调用失败，必须按本表落地。对照关系如下（左侧为用户样例里的写法）：

| 用户样例（伪契约） | 本技能实际调用 | 差异原因 |
|---|---|---|
| `query_stock_screen`: `stock_data.search_stocks(question=…)` | 同左，参数 `question` | 一致；「按市值降序」落成 `A股市值_不含限售股(亿元)` 排序（见 §1.3） |
| `query_business_verify`: `stock_data.get_financial_data_nl(question=…)` | `stock_data.get_stock_fundamentals(question=…)` | Wind `stock_data` 的自然语言工具名是 `get_stock_fundamentals`；`get_financial_data_nl` 不存在 |
| `query_valuation`: `stock_data.get_quote_snapshot(windcode, indexes="pe_ttm,pb,market_cap,roe")` | `stock_data.get_stock_price_indicators(windcode, indexes="中文简称,最新交易日,流通市值,总市值2,市盈率(TTM),市净率")` | 没有 `get_quote_snapshot`；`indexes` **只能用中文指标名**（英文名不存在）；`roe`/`revenue_yoy` 不在指标表内，改走 `get_stock_fundamentals`（Q-C） |
| `query_order_check`: `financial_docs.get_financial_news(query=…)` | 同左（+ `get_company_announcements` 双查询） | `financial_docs` **只含公告与财经新闻，不含券商研报**；研报口径只能走 `web_search` 并降置信度 |

| # | 要素 | 用户样例名 | **实际调用** | 关键参数 | 允许的 `source.type` |
|---|------|-----------|-------------|---------|---------------------|
| 1 | 概念股/行业股筛选（候选池） | `search_stocks` | `stock_data.search_stocks` | `question`（自然语言筛选条件） | `Wind 结构化数据` |
| 2 | 主营业务验证（占比） | `get_financial_data_nl` | `stock_data.get_stock_fundamentals` | `question`（实体+指标+报告期） | `Wind 结构化数据` |
| 3 | 估值与市值 | `get_quote_snapshot` + `pe_ttm,pb,market_cap,roe` | `stock_data.get_stock_price_indicators` | `windcode`（逗号分隔 ≤50）、`indexes`（逐字取指标表） | `Wind 结构化数据` |
| 4 | 订单/客户验证（RAG） | `financial_docs.get_financial_news` | `financial_docs.get_financial_news` | `query`、`top_k` | `Wind 新闻检索` / `公司公告` / `互联网查询` |

### 1.1 与用户样例的三处口径差异（必须遵守 Wind 官方契约）

| 事项 | 用户样例写法 | 实际契约 | 本技能处置 |
|------|-------------|---------|-----------|
| 快照工具名与字段名 | `get_quote_snapshot`，字段 `pe_ttm,pb,market_cap,roe` | `stock_data` **没有** `get_quote_snapshot`；时点快照工具是 `get_stock_price_indicators`，`indexes` **只能用中文指标名**（英文名不存在） | 用 `get_stock_price_indicators`，`indexes` 逐字取 `中文简称,最新交易日,流通市值,总市值2,市盈率(TTM),市净率` |
| 财务工具名 | `get_financial_data_nl` | `stock_data` 的自然语言工具是 `get_stock_fundamentals`（另有 `get_stock_basicinfo` / `get_stock_events` / `get_stock_equity_holders` / `get_risk_metrics` / `get_stock_technicals`） | 用 `get_stock_fundamentals` 取主营收入构成与 ROE；`roe`/`revenue_yoy` **不进 `indexes`** |
| 研报来源 | 隐含"研报可从 `financial_docs` 取" | `financial_docs` 仅含**公司公告与财经新闻**，明确**不含券商研报** | 订单/客户验证主路径 = `get_financial_news`（来源标 `Wind 新闻检索`）+ `get_company_announcements`（来源标 `公司公告`）；确需研报口径时走 `web_search`，标 `券商研报`/`互联网查询` 并降置信度 |

### 1.2 调用前必读

- `wind-mcp-skill` 的参数名、枚举、必填项一律**回其 `references/<领域>.md` 取**，不凭记忆填；
  `indexes` 逐字复制 `references/stock-indicators.md`，表内没有的字段不得猜测。
- 命令一律**在 `wind-mcp-skill` 技能目录内**以相对路径执行：
  `cd <wind-mcp-skill 技能目录> && node scripts/cli.mjs call <server_type> <tool_name> '<params_json>'`。
  **禁止**写死绝对路径、用户名或平台专有路径（本技能会被分享给他人）。
- 批量调用默认**串行**（并发 1）：同一 `server_type + tool_name` 先发**探针**，探针 exit 0 且无错误信封才继续其余；
  探针失败立即终止该批次，不得把相同调用扩散到其它标的。
- `get_stock_price_indicators` 的 `windcode` 单次最多 50 个；标的更多时按 ≤50 分批。

### 1.3 市值口径（硬性）

- 本技能固定 **`流通市值`**（与用户输出表列名一致），写入 `市值.index_field`；不得混用 `总市值1` / `总市值2`。
- `流通市值` 返回**字符串科学计数法**（如 `"4.66284e+10"`），元数据给出 `unit: 元`；
  换算为亿元由脚本完成（`元 ÷ 1e8`），**LLM 不得心算**。
- 候选池的 `A股市值_不含限售股`（亿元）仅用于候选排序与中位数校验；与快照不一致时以快照为准（`W_MCAP_OVERRIDE`）。
  **输出表、主口径、中位数一律 `流通市值`**，不得把候选池市值当结论展示。

## 2. 三条硬约束（强制）

### 硬约束 1：双查询法（趋势/验证类强制）

| 要素 | 查询 A | 查询 B | 说明 |
|------|--------|--------|------|
| 估值与市值 | 截至**最新交易日**的 `流通市值`、`市盈率(TTM)`、`市净率` | —— | 时点截面，单条即可 |
| 订单/客户验证 | `{公司} 在{事件相关领域}的最新订单或客户合作进展` | `{公司} 近2年的订单、客户定点或中标公告` | **两条禁止合并**；合并后 `dual_query.merged = true` 不用于本要素（本要素要求 A/B 分开发出） |

- `dual_query.current` / `history` 记录该条查询是否**实际发出并拿到回执**（空结果也算已发出，但须记入 `meta.降级说明[]`）。
- 只发一条时 `current=true, history=false`，并在 `证据` 或 `备注` 注明"仅最新口径"。

### 硬约束 2：时间范围四写法（禁止裸查询）

| 场景 | 标准写法 | 用在哪 |
|------|---------|--------|
| 最新值 | `截至最新交易日…` | 市值/估值快照 |
| 近 X 年 | `近2年的…` | 订单/客户验证历史序列 |
| 特定区间 | `2024-2026年的…` | 历史序列、订单累计 |
| 特定报告期 | `截至最新报告期…` / `2025年年度报告…` | 主营收入构成 |

- **禁止**裸查询：`"{方向}相关的上市公司"`、`"{公司}的订单"` 这类无时间状语写法一律不合格。
- 取数后必须把"最新"落成具体日期或报告期；无法确定时 `source.year` 写 `未标注`，置信度按 §6 降为**低**。

### 硬约束 3：单条查询 ≤ 6 指标 + 排名/筛选条件内嵌

- 单条查询指标数 `≤ 6`（模板库每条已标注）；超出按维度拆成多条**并行**发出。
- **排名/筛选条件必须写进自然语言，一次返回目标集合**：
  - ✅ `筛选A股中与{方向}相关的上市公司，按流通市值降序前15名，返回股票代码、股票名称、流通市值`
  - ❌ 先取"全部相关公司"再本地筛选
- 检索式长度 15–30 字；一条查询只承担一个分析维度；抽象框架词禁止（`行业景气度` → 换成 `订单、客户验证、主营构成`）。

## 3. 查询模板库

占位符：`{方向}` = A 内的标准方向名；`{公司}` / `{代码}` = 候选公司；`{领域}` = **该方向绑定事件的事件标题**（见 §3.1）。

### 3.1 `{领域}` 的取法（绑定驱动，强制）

1. `{领域}` **只能**取该方向在 `event-stock-mapper_binding_<日期>.json` 里的 `事件[].事件标题`；
   一个方向绑定多个事件时，订单/客户检索逐事件各发一次（`Q-E` 每事件一条），或按事件标题拼接，**不得**自行归纳成新的领域名。
2. 绑定表里没有该方向 → 该方向**不取数**（Step 4 会跳过），禁止用方向名或凭空构造的领域名代替
   （1.0 的「用方向名代替」做法已废弃，会破坏「事件↔环节」绑定）。
3. `{领域}` 与方向名不同时，检索式需同时出现公司与领域：`{公司} 在{领域}的最新订单情况或客户合作进展`。

| 代号 | 模板 | 工具 | 指标数 | 时间写法 |
|------|------|------|-------|---------|
| Q-A | `筛选A股中与{方向}相关的上市公司，按流通市值降序前15名，返回股票代码、股票名称、流通市值` | #1 | 3 | 最新值 |
| Q-B | `查询{公司}（{代码}）截至最新报告期的主营收入构成及各业务板块占比` | #2 | 2 | 特定报告期 |
| Q-C | `查询{公司}（{代码}）截至最新报告期的ROE、营业收入同比增速` | #2 | 2 | 特定报告期 |
| Q-D | `查询{代码}截至最新交易日的流通市值、市盈率TTM、市净率` | #3 | 3 | 最新值 |
| Q-E | `{公司} 在{领域}的最新订单情况或客户合作进展` | #4 | 2 | 最新值 |
| Q-F | `{公司} 近2年的订单、客户定点或中标公告` | #4 | 2 | 近 X 年 |

示例（仅示范写法，不得当作真实数据）：

```
Q-A → "筛选A股中与固态电解质相关的上市公司，按流通市值降序前15名，返回股票代码、股票名称、流通市值"
Q-B → "查询天赐材料（002709.SZ）截至最新报告期的主营收入构成及各业务板块占比"
Q-D → "查询002709.SZ,300037.SZ截至最新交易日的流通市值、市盈率TTM、市净率"
Q-E → "天赐材料 在固态电解质的最新订单情况或客户合作进展"
```

**参数落位示例**（在 `wind-mcp-skill` 目录内执行）：

```bash
cd <wind-mcp-skill 技能目录>
node scripts/cli.mjs call stock_data search_stocks \
  '{"question":"筛选A股中与固态电解质相关的上市公司，按流通市值降序前15名，返回股票代码、股票名称、流通市值"}'
node scripts/cli.mjs call stock_data get_stock_fundamentals \
  '{"question":"查询天赐材料（002709.SZ）截至最新报告期的主营收入构成及各业务板块占比"}'
node scripts/cli.mjs call stock_data get_stock_price_indicators \
  '{"windcode":"002709.SZ,300037.SZ","indexes":"中文简称,最新交易日,流通市值,总市值2,市盈率(TTM),市净率"}'
node scripts/cli.mjs call financial_docs get_financial_news \
  '{"query":"天赐材料 在固态电解质的最新订单情况或客户合作进展","top_k":10}'
node scripts/cli.mjs call financial_docs get_company_announcements \
  '{"query":"查询天赐材料近2年的订单、客户定点或中标公告","top_k":10}'
```

**回执解析要点**：

- `search_stocks` 返回 `Wind代码 / 证券简称 / A股市值_不含限售股(亿元) / 交易币种 / 所属概念板块`；
  只保留 `A股` + `CNY`，港美股代码（`.HK`/`.O`/`.N`）一律剔除。
- `get_stock_fundamentals` 返回 `最新一期主营收入构成` 字符串，形如
  `锂离子电池材料产品:93.05%;个人护理品材料产品:4.67%;其他:2.28%`，并给出 `.类型`（如 `按产品`）。
- `get_stock_price_indicators` 返回列名与 `unit`（`流通市值`/`总市值2` 的单位为**元**），值为字符串科学计数法。
- `null` 表示缺失或不适用，**禁止当作 0**；仅报告实际返回的行数，不得据 `excelTotalCount` 推断全量。

## 4. 主营构成占比的解析与口径判定（关键）

`get_stock_fundamentals` 的占比是**业务口径**，通常**大于** A 中的细分方向口径，必须显式降级：

| 步骤 | 做法 |
|------|------|
| 1 取行 | 从 `最新一期主营收入构成` 中选出与方向最相关的业务行，`业务行` 逐字记录原文名 |
| 2 判口径 | 业务行口径 **⊇** 方向口径（如方向"固态电解质" vs 业务行"锂离子电池材料产品"）→ `precision="近似"`、`caliber_vs_target="偏大"`、`tag="[待验证]"` |
| 3 直接命中 | 业务行就是该方向（如方向"六氟磷酸锂" vs 业务行"六氟磷酸锂"）→ `precision="精确"` |
| 4 无法对应 | 所有业务行都与方向无关 → `业务占比` 写 `null`（走 T5 降档），并记 `meta.降级说明[]` |

- **口径偏大不得作为核心受益命中**（脚本按 T6 处理并记 `W_CALIBER_OVERSIZE`），只能进次要受益/观察标的。
- 占比值保留 Wind 原文精度换算为小数（`93.05% → 0.9305`）；**禁止**把多个业务行相加后充当单一方向占比，
  除非在 `caliber` 中明确声明合并口径并标 `[待验证]`。

## 5. 订单/客户验证的判定

| 判定 | 成立条件 | 可计入的证据 |
|------|---------|-------------|
| `有 = true` | 检索回执中**明确出现**该公司的订单、客户定点、中标、供货协议、批量交付 | 公告原文、新闻原文、定点/中标通知 |
| `有 = false` | 检索已发出但未命中，或只命中"送样""研发合作""战略框架"等**非订单**表述 | 记 `证据: ""`，`dual_query` 留痕 |

- **禁止**把研报观点、行业空间、股价异动当作订单证据。
- 来源优先级：`公司公告`（原文可核验）> `Wind 新闻检索` > `互联网查询`；前两者可判「高/中」，互联网来源不得判「高」。
- 每条 `证据` 必须能一句话说清"谁向谁下了什么"，不得写"订单饱满""需求旺盛"这类不可核验表述。

## 6. 来源与置信度判定

### 6.1 三维修正（取**最保守**结论）

| 维度 | 高 | 中 | 低 |
|------|----|----|----|
| 来源权威性 | `Wind 结构化数据` / `公司公告` / `政府文件` | `Wind 新闻检索` / `券商研报` | `互联网查询` |
| 口径匹配 | 与目标口径一致（含 `precision=精确`） | 口径偏大但同产业链 | 口径偏大且跨层，或年份不明 |
| 时效 | 落在最新交易日/最新报告期 | 落后 ≤1 年 | 落后 >1 年或 `未标注` |

- 最终 `confidence ∈ {高, 中, 低}`，三维修正过程写入一行 `confidence` 依据（可放 `备注`）。
- **机械规则**：`source.type = 互联网查询` 或 `source.detail` 含第三方机构名（QYResearch、TrendForce、GGII、弗若斯特沙利文、IDC 等）时，`confidence` **不得为「高」**；违反 → 自动降为「中」并记 `W_CONFIDENCE_UPGRADED`。

### 6.2 口径降级三条件（脚本强制）

当精确口径查不到、改用近似口径替代时，必须同时满足：

1. 显式声明 `precision = "近似"`；
2. 说明 `caliber_vs_target ∈ {偏大, 偏小}` 与 `caliber`；
3. `tag = "[待验证]"`，且 `source.detail` 写清来源与年份。

缺一 → `E_APPROX_CALIBER_INCOMPLETE`；`偏大` 口径按 `tiering-rules.md` T6 处理。

### 6.3 单位与换算边界

- `config.units.流通市值` 是**已声明单位集合**；元素内市值单位必须落在集合内，否则 `E_SCHEMA`。
- 换算统一到**人民币亿元**，保留 2 位小数；汇率不涉及（只做 A 股 + CNY）。
- 禁止自造单位（`千亿元`、`万美元`）与静默换算。

### 6.4 Fallback 顺序

```
stock_data 无结果 → financial_docs 提取公司名（get_company_announcements / get_financial_news）
  → web_search 补充 → 标 [数据暂不可用] + 记入 meta.降级说明[]
financial_docs 无结果 → web_search → 标 [文档信息暂不可用] + 记入 meta.降级说明[]
Wind 未就绪（探针 AUTH_ERROR 且明确未配置）→ 输出「未就绪提示语」→ 用户确认后才允许仅用 web_search
```

> ⚠️ **绝对禁止**：任何层级的 fallback 耗尽后，禁止虚构数字、公司名、股票代码或来源标注；
> 只能标注缺失，并说明它对档位判断的影响（占比缺失 → 降档并标 `[待验证]`；市值缺失 → 不入池/展示为 `[数据暂不可用]`）。

## 7. 查询构造自检（逐条核对，全过才进 Step 3）

```
□ R1 每个 A 内方向是否都发了 Q-A（排名条件内嵌，未先取全列表再本地筛）？
□ R2 每条查询是否带四种时间写法之一（无裸查询）？"最新"是否已落成具体日期/报告期？
□ R3 每条查询指标数是否 ≤6？
□ R4 订单/客户验证是否 A/B 双查询（或明确说明只发了最新口径）？
□ R5 `indexes` 是否逐字取自 wind-mcp-skill 的 stock-indicators.md？
□ R6 市值口径是否为 `流通市值`（未混用总市值1/2）？
□ R7 主营构成占比是否按 §4 判定了口径（精确/近似/无对应）？偏大是否标 `[待验证]`？
□ R8 每个数据点是否都有 source.type、source.detail|year 与 confidence？
□ R9 互联网/第三方来源是否未标「高」？
```
