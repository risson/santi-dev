# 定档、截取与排序规则（单一真源）

本文件定义 Step 4 的全部判定。脚本 `event-stock-map.mjs` 按本文件实现，`SKILL.md` 只引用不重复。
**LLM 不得手算本文件任何结论。**

---

## 1. 层级定档（T1–T6，按顺序命中即停）

判定输入：`业务占比.value`（`shareValue`）、`业务占比.precision` / `caliber_vs_target`、`订单验证.有`。

| 序号 | 条件 | 结果 | 说明 |
|------|------|------|------|
| **T1** | `shareValue > 0.20` **且** `订单验证.有 == true` **且** 非「口径偏大」 | **核心受益** | 占比达标 + 有明确订单/客户验证 |
| **T2** | `shareValue > 0.20` 且 `订单验证.有 == false` | **次要受益** + `W_NO_VERIFICATION` | 占比达标但未取得订单/客户验证 → 降档 |
| **T3** | `0.05 ≤ shareValue ≤ 0.20` | **次要受益** | 位于 5–20% 区间 |
| **T4** | `shareValue < 0.05` | **观察标的** | 主题纯正或逻辑待验证 |
| **T5** | `业务占比` 缺失（`null`） | 最高只能到次要受益；若同时无订单验证 → **观察标的**；记 `W_SHARE_MISSING` | 降档 + `[待验证]` |
| **T6** | `precision == "近似"` **且** `caliber_vs_target == "偏大"` | **不得**作为 T1 命中：`shareValue ≥ 0.05` → 次要受益；`shareValue < 0.05` → 观察标的；记 `W_CALIBER_OVERSIZE` | 口径大于方向本身 |

**边界口径（与规则一一对应，selftest 强制）**

- `shareValue` 恰好 `0.20` → **不算** T1（`>` 而非 `≥`），按 T3 走次要受益。
- `shareValue` 恰好 `0.05` → 属 T3（`≥ 0.05`），次要受益。
- T6 与 T1 同条件命中时 **T6 优先**（先判口径是否偏大）。
- T2 与 T3 的差异只在占比区间：`>0.20` 无验证记 `W_NO_VERIFICATION`，`≤0.20` 不记。

**市值弹性（只进解读，不参与定档）**

```
弹性大  ⇔  该股流通市值 ≤ 同方向候选池流通市值中位数
弹性中  ⇔  该股流通市值 >  同方向候选池流通市值中位数
弹性 = null ⇔ 该股流通市值缺失（不臆造）
```

- 中位数由脚本按候选池可得市值升序取中位（偶数取中间两值均值，保留 2 位小数）；候选池市值全部不可得 → 中位数 `null`，
  一律按「小」表述并记 `W_ELASTICITY_UNDEFINED`。
- **禁止**把弹性与档位互相推导（例如"市值小所以升为核心受益"）。

## 2. 截取（每方向 5–8 只）

> 前置条件：只有**通过了事件绑定校验**的方向才进入本节（见 `data-schema.md`「绑定门禁」与 `SKILL.md` Step 4）。
> 被跳过的方向不取数、不定档、不计入 `top_min` / `top_max` 与档位配比校验，只在 `meta.跳过方向[]` 与绑定表中留痕。

1. 按 `核心受益 → 次要受益 → 观察标的` 分组，组内按**流通市值升序**（弹性优先），市值缺失者押尾，同市值按股票代码字典序。
2. 每组按 `tier_max` 截取上限：核心受益 ≤4、次要受益 ≤3、观察标的 ≤2；被截断项记入 `方向摘要[].被截断` 并记 `W_TIE_CUT`。
3. **回补**：截取后总数 < `top_min`（默认 5）时，从被截断项中按流通市值升序回补，直到达到 `top_min` 或无可回补项。
4. 总数 > `top_max`（默认 8）时截到 `top_max`。
5. 入池后总数仍 < `top_min` → `E_LT_MIN_POOL`（不虚构补足）。
6. 截取/回补后档位配比不在 `tier_min–tier_max` 之间 → `E_TIER_COUNT`。

**市值缺失的处置（硬性）**：不写 0；该标的计入入池数但展示为 `[数据暂不可用]`；若因此使入池数 < `top_min` → `E_LT_MIN_POOL`。
候选池市值也可为空（`mcap: null`），此时由快照市值补齐供中位数使用。

## 3. 排序（结果 JSON 与 7 列主表同序）

```
① 产业方向   = A 的输入顺序（A 来自 `extract` 时 = 前序「通过」顺序 / 标准名字典序）
② 推荐层级   = 核心受益(1) > 次要受益(2) > 观察标的(3)
③ 流通市值   = 升序（市值缺失押尾）
④ 股票代码   = 字典序（稳定兜底）
```

- 同一股票出现在多个方向时，**每个方向各出一行**（记 `W_MULTI_DIRECTION`），同方向内不得重复。
- 「按产业方向、推荐层级排序输出」即指本三键 + 代码兜底，不得改用其他排序。

## 4. 层级解读模板（脚本生成，禁止 LLM 自由写）

| 档位 | 模板 |
|------|------|
| 核心受益 | `相关业务占比 {p}%[（近似口径[待验证]）] + {有明确订单/客户验证} + 市值 {m} 亿元（方向内中位数 {med} 亿元，弹性{大\|中}）` |
| 次要受益 | `相关业务占比 {p}% + {占比>20% 但未取得订单/客户验证 \| 占比>20%（口径偏大，按规则不计为核心受益）\| 占比位于 5–20% 区间 \| 占比不可得（已降档 [待验证]）} + {弹性说明}` |
| 观察标的 | `{业务占比 X%（<5%，主题纯正或逻辑待验证）\| 业务占比[数据暂不可用]，已降档 [待验证]} + {弹性说明}` |

- `{p}` 保留 2 位小数；`{m}` / `{med}` 千分位 + 2 位小数 + ` 亿元`。
- 市值缺失时弹性段替换为 `市值[数据暂不可用]`。
- 解读必须与 `定档依据`（T1–T6）一致；主表不得出现空单元格（脚本强制 `E_SCHEMA`）。

## 5. 原因码汇总

| 码 | 类型 | 含义 |
|----|------|------|
| `W_SHARE_MISSING` | 警告 | 主营构成占比不可得 → 降档（T5） |
| `W_CALIBER_OVERSIZE` | 警告 | 口径偏大 → 不得命中核心受益（T6） |
| `W_NO_VERIFICATION` | 警告 | 占比达标但无订单/客户验证 → 降档（T2） |
| `W_MCAP_MISSING` | 警告 | 市值缺失（不补 0） |
| `W_ELASTICITY_UNDEFINED` | 警告 | 候选池市值全缺失，中位数不可算 |
| `W_TIE_CUT` | 警告 | 档位超上限被截断 |
| `W_MULTI_DIRECTION` | 警告 | 同股跨方向 |
| `W_MCAP_OVERRIDE` | 警告 | 候选池市值被快照市值覆盖 |
| `E_LT_MIN_POOL` | 阻断 | 入池后不足 `top_min` |
| `E_TIER_COUNT` | 阻断 | 档位配比不合规或总数超 `top_max` |

## 6. 判定自检

```
□ 是否用小数比较（0.20 / 0.05），而非百分数？
□ 恰好 20% 是否未判为核心受益？恰好 5% 是否判为次要受益？
□ T6（口径偏大）是否优先于 T1，且未作为核心受益命中？
□ T2/T3 的告警区分是否正确（只有 >20% 无验证才记 W_NO_VERIFICATION）？
□ 占比缺失是否降档并标 [待验证]（未臆造占比、未直接淘汰）？
□ 弹性是否只影响解读与组内排序，未参与定档？
□ 截取上限是否 4/3/2？总数是否落在 5–8？
□ 每方向档位是否满足 3–4 / 2–3 / 1–2？
□ 排序是否严格三键 + 代码兜底？同股跨方向是否各出一行？
□ 主表 7 列是否逐字固定、无空单元格（含第 2 列产业链层级）？
```
