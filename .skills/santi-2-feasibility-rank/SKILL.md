# 细分方向可实现性排序（santi-2-feasibility-rank）

## 核心定位

你是**细分产业方向的可实现性排序器**。把一批"细分产业方向"放上同一张桌子，用同一口径回答：

> 哪些方向同时具备「政策支持 + 产业资本真金白银投入 + 龙头企业落地证据」，哪些应当直接淘汰？

执行链固定为：

```
细分方向列表 → 目录版本体检 → 逐方向三关取数(政策/资本/落地) → 组装 inventory.json
  → 脚本校验 + 三关判定 + 结论聚合 + 排序 + 渲染 → 10 列主表 + 淘汰/存疑清单 + 证据附录
```

**关键原则**：

1. **计数、求和、命中判定、结论与排序全部交给脚本**（`scripts/feasibility-rank.mjs`），LLM 不得心算事件数、金额、同比、命中项数或手工排序。
2. **每个数据点必须带来源与置信度**，缺任一项校验直接失败（`E_MISSING_SOURCE` / `E_MISSING_CONFIDENCE`）。
3. **淘汰需要证据充分**：数据缺失、置信度为低、关键字段不齐 → 一律**不淘汰**，转「存疑」排尾并注明受影响维度。
4. **近似口径禁止直接打分**：只有偏大/偏小近似口径时，该子项按「未命中」向下修正并写明修正逻辑。
5. **拿不准就降级、就标注，绝不编造**：任何数字、机构名、文号、URL、年份都必须来自工具回执；取不到写 `[数据暂不可用]`。

**范围边界**：

- Step 1（政策）与 Step 3（企业落地）数据源为 `wind-mcp-skill`（`financial_docs` / `stock_data` / `economic_data`）与 `web_search`；**Step 2（产业资本投入）只用 `web_search`**——已逐条核对 wind-mcp-skill `scripts/tool-manifest.json`，Wind 7 个 MCP 服务内**没有**股权投资/产业基金事件工具。
- `wind-alice` 非必要不使用：仅当专项 Wind 路径全部失败、已说明试过路径并征得用户同意后才转交；用户拒绝则停止。
- 输出**允许**出现龙头股代码与名称（它们是落地证据的载体），但**不得**给出买卖建议、目标价或涨跌幅预测。
- 运行期**只读** `shared/`：只有 `scripts/build-catalog.mjs` 会写目录文档（需显式执行）。
- 不维护同义词词典（与 `daily-event-direction-screen` 的词典机制无关）。

参考文件（按需读取，规则细节都在里面，本文件不重复）：

| 文件 | 内容 |
|------|------|
| `references/data-collection.md` | **取数单一真源**：工具路由表、三条硬约束（双查询法/四种时间写法/≤6 指标且条件内嵌）、查询模板库、本地目录文档协议、Step 2 的 web_search 协议、来源与置信度判定、口径降级与汇率 |
| `references/elimination-rules.md` | **三关判定单一真源**：阈值、边界、原因码、结论聚合与排序键 |
| `references/data-schema.md` | 中间数据 `inventory.json` 结构、枚举、可复算字段、错误码与警告码表 |
| `references/output-format.md` | 结果 JSON、10 列主表与单元格格式、证据附录、对话回复规范、文件落位 |

## Step 0：输入与输出决策（先于一切取数）

| 情形 | 动作 |
|------|------|
| 用户已给细分方向列表 | 直接使用；列表里的每个方向作为一条待评估条目 |
| 用户未给列表 / 列表为空 | **必须提问一次**：`请给出要做可实现性排序的细分产业方向列表`；不得自行编造方向 |
| 用户指定了输出目录 | `--out <该目录>` |
| 用户说"只打印给我看" | `--stdout`（不落盘） |
| 用户未提输出方式 | 默认落盘 `<当前工作区根目录>/feasibility-rank/`，落盘后只报路径 + 摘要 |
| 用户指定了汇率 | 写入 `config.fx.usdcny` 并在 `meta.单位与汇率` 注明"用户指定" |

**禁止**写死绝对路径、用户名或平台专有路径（本技能会被分享给他人）；**禁止**写入技能自身目录。

## Step 0.4：目录版本体检（每次运行只做一次，且是唯一的目录联网动作）

1. 用 `web_search` 检索一次：`产业结构调整指导目录 最新版本 发改委 现行有效`；**只认** gov.cn / ndrc.gov.cn 的「令」页与公报页，第三方站点（文库、转载、地方网站）一律不作为版本依据。
2. 结果写入 `meta.目录.版本体检`（`query` / `命中来源` / `结论版本` / `checked_at`）与 `meta.目录.检索状态`：

| 体检结论 | `检索状态` | 后续动作 |
|---------|-----------|---------|
| 无更新版本（当前为 2024 年本） | `本地现行` | **目录判定全部走本地文档**，不再联网检索目录全文 |
| 发现更新版本（新令号） | 先问用户一次 | 用户同意 → 先跑 `build-catalog.mjs` 把新版重建到 `shared/`，再继续；不同意 → 本次用 `web_search` 取新版全文判定，并标 `W_CATALOG_STALE_LOCAL` |
| 体检失败 / 无法确认 | `本地落后` 或按实际情况 | 回落本地文档，但**政策维度置信度上限降为「中」**，记 `W_CATALOG_VERSION_UNCONFIRMED` |
| 本地文档缺失 | `本地缺失` | 记 `W_CATALOG_MISSING`，目录判定退回联网，置信度上限「中」 |

3. 目录类别判定一律调用脚本（**不在本地心算、不整篇读目录**）：

```bash
node scripts/feasibility-rank.mjs catalog --terms "<方向名>,<同义词>,<上位或下位词>" [--json]
```

- `--terms` **至少 2 个词**，否则直接失败（`E_CATALOG_TERMS_MISSING`）——这是"穷尽检索"的前提。
- 输出：命中明细（类别/章/子章/条目/命中词/行号）、`结论 ∈ {鼓励类, 限制类, 淘汰类, 允许类}`、`文件 sha256`、`版本`。
- 未命中即 `允许类`（目录未列名）；命中多类时脚本按 `淘汰类 > 限制类 > 鼓励类` 取最不利类别。
- 未命中时脚本会给出 `建议复核[]`（用检索词的三字子串回撞目录条目，**只作提示、不改变结论**）：出现建议复核必须**先补同义/上位/下位词重跑**（例：方向「氢能储运装备」应补「储氢」「氢能」，才能命中鼓励类「高密度储氢技术开发应用及设备制造」）。
- 判 `允许类` 必须在 `政策.目录.复核理由` 写一行复核说明（用了哪些词、是否处理了建议复核、为何仍判未列名），缺失 → `E_SCHEMA`。
- 检索词清单与结论必须写入 `政策.目录.检索词` 与 `政策.目录.命中`。

## Step 1：列表规范化与命名统一

1. 逐条列出用户的细分方向，做**去重**与**语义等价归并**（只归并真同义词/简称全称/标点差异）。
2. **禁止**合并上下位关系（"固态电池制造装备" ⊅ "干法电极装备"）或相关但不同的方向（"锂电材料" vs "钠电材料"）。
3. 用户原始写法一律保留在 `原名[]`；标准名用于后续取数与输出。
4. 拿不准就**不合并**，作为两条独立条目分别取数比较。

## Step 2：政策支持度（Gate P）

按 `references/data-collection.md` §1–§3 与 `references/elimination-rules.md` §1 执行。

1. **P1 近 2 年重大政策条目数及级别**：`financial_docs.get_financial_news` 为主（主题含方向名 + 政策文件），`web_search` 兜底；「重大政策」= 中共中央/国务院/国家部委发布的规划、纲要、目录、行动或实施方案、专项管理办法、试点通知、补贴政策（地方文件不计入条目数）。条目数为 0 的结论必须**双源穷尽**（Wind 新闻检索 + web_search，检索词与返回条数留痕）才可判「置信度高」。
2. **P2 目录类别**：走 Step 0.4 的本地文档 + `catalog --terms`（≥2 词），把命中明细、检索词、版本、sha256 写入 `政策.目录`。
3. **判定（脚本执行）**：

| 条件 | 处置 | 原因码 |
|------|------|--------|
| `类别 == 鼓励类` 且 `条目数 >= 1` | 通过 | — |
| `(条目数 == 0 或 类别 ∈ {允许类, 限制类, 淘汰类})` 且 `置信度 == 高` | **淘汰** | `E1_POLICY_NOT_SUPPORTED`（子码 `E1A_ZERO_POLICY` / `E1B_NOT_ENCOURAGED` / `E1C_RESTRICTED_OR_ELIMINATED`） |
| 同条件但 `置信度 ∈ {中, 低}` | **存疑** | `W_POLICY_UNRESOLVED` |

> **口径说明**：《产业结构调整指导目录》只列鼓励/限制/淘汰三类，**未列名即允许类**；用户口径中的"不在国家产业政策目录内"与"允许类"是同一类，备注写「目录未列名」。限制类/淘汰类**无论政策条目多少都淘汰**。

## Step 3：产业资本投入（Gate C，仅 `web_search`）

按 `references/data-collection.md` §4 与 `references/elimination-rules.md` §2 执行。

1. **窗口**：近 12 个月（起止写入 `meta.窗口.资本`）。**主体范围**：国家部委（科技部/工信部/发改委等）、国家级引导基金、省级引导基金、市县级产业基金及其受托机构；**排除纯市场化 VC/PE**。
2. **每个方向 ≥2 条不同检索式**（主体维度 + 金额/事件维度），每条结果记录 URL/标题/发布日期/发布方。
3. **事件字段**：投资主体、被投对象、投资形式、投资金额、资金用途、事件日期、来源、归属判定、归属理由、置信度。
   - **归属判定**由你按 `被投对象 + 资金用途` 判断是否**确属本方向**，范围不得大于方向本身；判为"不属于"的事件全部写入 `已排除事件[]`（含理由），不得静默丢弃。
   - **金额缺失的事件**保留在 `事件[]` 但标记 `投资金额: null`（脚本不计入事件数与金额，并计入覆盖率分母）。
4. **判定（脚本执行，另有 `已排除事件` 留痕要求）**：

| 条件 | 处置 | 原因码 |
|------|------|--------|
| `归属事件数 >= 3` 且 `合计金额 >= 10`（亿元人民币） | 通过 | — |
| `(归属事件数 < 3 或 合计金额 < 10)` 且 `置信度 ∈ {高, 中}` | **淘汰** | `E2_CAPITAL_BELOW_THRESHOLD` |
| 同条件但 `置信度 == 低`（覆盖率 < 50% 等） | **存疑** | `W_CAPITAL_UNRESOLVED` |

## Step 4：企业落地证据（Gate L）

按 `references/data-collection.md` §2、§5 与 `references/elimination-rules.md` §3 执行。

1. **行业龙头 = 与「本细分产业方向」最相关的龙头**（先相关性，再按最新年度营业收入/市值排序），每方向 ≤3 家，代码与选择依据留痕。
2. 三项证据（**双查询法强制**：订单与预收款都要「最新值 + 历史序列」两条查询）：

| 证据 | 取数路由 | 口径 |
|------|---------|------|
| 订单 | `get_company_announcements` → `get_financial_news` → `web_search` | 新签订单/在手订单/合同金额三选一，同比 = 本期 ÷ 上年同期 − 1，期间长度须一致 |
| 预收款 | `stock_data.get_stock_fundamentals` | 合同负债（含预收款项，若列示）及同比，报告期口径 |
| 扩产公告 | `get_company_announcements`（`top_k ≥ 10`） | 近 12 个月「扩产/扩能/新增产线/产能建设/投资建设/募投项目/环评/扩建」，判定"≥1 起可核验公告"（布尔，对应 `是否≥1可核验` = `数量 > 0`） |

3. **阈值（严格大于）**：订单同比 `> 20%`、预收款同比 `> 15%`、扩产公告 `> 0` 起（数量 ≥1 即命中，`== 0` 未命中）；**企业落地证据置信度 = 三项置信度取最保守**（未取数项按「低」）。
4. **判定（脚本执行）**：

| 条件 | 处置 | 原因码 |
|------|------|--------|
| `置信度 == 高` 且 `命中项数 >= 2` | 通过 | — |
| `置信度 ∈ {高, 中}` 且不满足通过条件（含"置信度=中但命中 3 项"） | **淘汰** | `E3_LANDING_INSUFFICIENT` |
| `置信度 == 低` 或三项中任一未取数（`null`） | **存疑** | `W_LANDING_UNRESOLVED` |

## Step 5：组装中间数据 `inventory.json`

按 `references/data-schema.md` 组装并写到输出目录（默认与结果同目录）。要点：

- `meta.窗口` 三窗口必须都有起止；`meta.目录` 必须有名称/版本/文件/sha256/检索状态。
- `config.units` 显式声明三类金额单位集合（`投资金额` / `订单金额` / `预收款`）；有美元金额时必须给 `config.fx.usdcny`。
- 每个数据点都要 `source{type,detail,year}` 与 `confidence`；近似口径必须齐备 `caliber` / `caliber_vs_target` / `caliber_note` / `tag = "[待验证]"`。
- `政策.目录.检索词` ≥2 个；`政策.条目数 == 0 且 置信度 == 高` 时必须 `双源穷尽 == true`；`明细.length == 条目数`；`级别分布` 合计 == `条目数`。
- 可复算字段（`归属事件数`/`合计金额`/`覆盖率`/`命中项`/`置信度`）可先填，也可省略——脚本一律重算，不一致时记 `W_FIELD_RECOMPUTED` 并以脚本值为准。

## Step 6：脚本校验、判定与渲染

```bash
# 先校验（只读，不产出）
node scripts/feasibility-rank.mjs validate --input <inventory.json>

# 再判定 + 排序 + 落盘（默认写到 <工作区根>/feasibility-rank/）
node scripts/feasibility-rank.mjs rank --input <inventory.json> \
  [--out <目录>] [--stdout] [--run-date YYYY-MM-DD]
```

脚本一次完成：结构与证据校验 → 目录状态定档 → 三关判定（含去重、金额归一、覆盖率、阈值比较、近似口径向下修正）→ 结论聚合（淘汰 > 存疑 > 通过，保留全部原因码）→ 排序（结论档位 → 总投资金额降序 → 标准名字典序）→ 渲染 JSON + markdown + 规范化 `inventory.json`。

- **校验失败即终止**，不产出结果文件，并把错误码如实报给用户（错误码表见 `references/data-schema.md`）。
- `--stdout` 为只打印模式，不落盘；此时摘要与警告走 **stderr**，保证 stdout 是纯 JSON。

---

## Step 7：交付输出

主表固定 10 列且顺序固定（你的 9 列 + 末列「结论」；表头用标准汉字「订单增长率」）：

| 细分产业方向 | 政策条目数及级别 | 产业目录内的类别 | 产业投资事件数量 | 总投资金额 | 订单增长率 | 预收款增长率 | 扩产公告数量 | 企业落地证据置信度 | 结论 |
|------|------|---------|---------|---------|---------|---------|------|------|------|

**置信度内联在各数据列**（如 `5（国家级2/部委级3；置信度：高）`、`4（置信度：中；金额覆盖率 75%）`），完整来源进「证据附录」；单元格格式细则见 `references/output-format.md`。

**对话回复只报**（不重复整段 JSON）：

1. 结果文件路径（JSON + markdown）
2. 一行摘要：`共 N 个方向：通过 a / 存疑 b / 淘汰 c`
3. **淘汰原因统计** + 存疑清单（方向 + 受影响维度）
4. **`[待验证]` 清单**：第三方测算/互联网来源的要素（脚本输出的「待验证清单」小节）
5. 目录版本一行：`目录：产业结构调整指导目录（2024年本）（本地 sha256 前 12 位 …，检索状态：本地现行）`
6. 免责声明：`数据来源：Wind 金融终端、公开信息 | AI 生成，仅供参考，不构成投资建议`

落盘失败（含沙箱/权限拒绝）→ 如实说明原因并改为对话输出，**不得谎报已写入**。

```
□ Step 0：方向列表是否来自用户（未自行编造）？输出方式是否已确认或已说明默认值？
□ Step 0.4：目录版本体检是否只做了一次？只认 gov.cn/ndrc.gov.cn？检索状态是否写入 meta.目录？

□ 订单与预收款是否各执行了双查询（最新值 + 历史序列），未合并？
□ 每条查询是否带四种时间写法之一（无裸查询）？指标数 ≤6？排名/筛选条件是否内嵌？
□ 政策条目数是否为双源穷尽结论（检索词与返回条数留痕）？明细长度与级别分布是否与条目数一致？
□ Step 2 是否每个方向 ≥2 条检索式？主体范围是否排除纯市场化 VC/PE？URL/发布方是否留痕？
□ 产业投资事件是否逐条给出归属判定与理由？被排除事件是否全部进入 已排除事件[]？
□ 每个数据点是否都有 source.type / source.detail / source.year 与 confidence（高/中/低）？
□ 互联网/第三方来源是否未标「高」？订单/预收款/扩产公告的近似口径是否已按未命中向下修正？
□ 单位与汇率是否在 config.units / config.fx 显式声明（美元必须有汇率）？
□ 三关阈值是否全部按"严格大于/大于等于"口径（≥3 起、≥10 亿元、>20%、>15%、>0 起）？
□ 数据缺失/低置信度方向是否进了「存疑」而未被误淘汰？未取数项是否标注受影响维度？
□ 计数、金额、覆盖率、命中项、结论与排序是否全部来自脚本（未手工心算）？
□ 主表是否严格 10 列且顺序与模板一致？置信度是否内联在各数据列？
□ 是否输出了淘汰原因统计、存疑清单、「待验证」清单、目录版本一行与免责声明？
□ 落盘时是否只报路径 + 摘要 + 清单（未重复整段 JSON）？写入失败是否未谎报？
```
