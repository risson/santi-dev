## 2. 三条硬约束（强制，三关通用）

### 硬约束 1：双查询法（趋势判断强制触发）

凡涉及**趋势判断**或**历史分位**的要素必须成对查询，缺一不可、禁止合并：

| 要素 | 查询 A（最新值） | 查询 B（历史序列） |
|------|-----------------|-------------------|
| 订单同比 | `查询{龙头}截至最新期间的订单（新签订单/在手订单）` | `查询{龙头}近2年的新签订单/在手订单历史数据` |
| 预收款同比 | `查询{龙头}截至最新报告期的合同负债、预收款项` | `查询{龙头}2023-2025年各季度的合同负债、预收款项` |
| 政策条目数（跨年趋势时） | `{方向}近2年的重大政策文件` | `{方向}近5年的重大政策文件及级别` |
| 目录类别（版本更替时） | `截至最新版本的目录中{方向}的类别` | `2024年本与最新版本目录中{方向}的类别对比` |

- 两条**禁止合并**为一条；合并后 `dual_query.merged = false` → 校验失败（`E_DUAL_QUERY_MISSING`）。
- `dual_query.current` / `dual_query.history` 记录该条查询是否**实际发出并拿到回执**（空结果也算已发出，但须记入 `meta.降级说明[]` 并记 `W_DUAL_QUERY_EMPTY`）。

### 硬约束 2：时间范围四写法（禁止裸查询）

| 场景 | 标准写法 | 本技能用在哪 |
|------|---------|-------------|
| 最新值 | `截至最新交易日…` / `截至最新报告期…` | 预收款最新期、市值/行情 |
| 近 X 年 | `近2年的…` | 政策条目数、订单与预收款历史序列 |
| 特定区间 | `2023-2025年的…` | 历史序列、版本对比 |
| 特定报告期 | `2025年第3季度的…` | 预收款单期值、订单单期值 |

- 资本与扩产窗口批准使用 `近12个月的…`（属"近 X 年"的等价写法，须在 `meta.窗口` 显式声明起止）。
- **禁止**裸查询：`"{方向}的政策"`、`"{方向}的订单"` 这类无时间状语写法一律不合格。
- 取数后必须把"最新"落成具体日期或报告期；无法确定时 `source.year` 写 `未标注`，置信度按 §6 降为**低**。

### 硬约束 3：单条查询 ≤ 6 指标 + 排名/筛选条件内嵌

- 单条查询指标数 `≤ 6`（模板库每条已标注）；超出按主题拆成多条并行。
- 排名/筛选条件必须写进自然语言一次返回目标集合：✅ `"筛选{方向}相关A股上市公司按营业收入降序前10名"`；❌ 先取全列表再本地筛。
- 检索式长度建议 15–30 字；一条查询只承担一个分析维度；抽象框架词禁止（`行业景气度` → 换成 `订单、预收款、扩产公告`）。

## 3. 本地目录文档协议（Gate P 的 P2 判定）

### 3.1 文件与结构

- 路径：`<工作区根>/shared/产业结构调整指导目录（2024年本）.md`（由本技能 `scripts/build-catalog.mjs` 生成；规则见该脚本头部注释）。
- 结构（**唯一权威定义**）：

```
# 产业结构调整指导目录（2024年本）
## 元信息            # 表格：版本/文号/施行日期/主源/源文件 SHA256/结构统计/交叉校验
## 总则与目录说明     # 含"鼓励类、限制类和淘汰类之外的……属于允许类"
## 第一类 鼓励类
### 一、农林牧渔业
1.……
## 第二类 限制类
### 一、农林牧渔业
1.……
## 第三类 淘汰类
### 一、落后生产工艺装备
#### （一）农林牧渔业
1.……
### 二、落后产品
#### （一）石化化工
1.……
```

- 目录页（TOC）已省略，避免与正文标题重复导致章数虚增。

### 3.2 使用协议

1. **每次运行只做一次版本体检**（Step 0.4）：`web_search` 检索「产业结构调整指导目录 最新版本 发改委 现行有效」，只认 gov.cn / ndrc.gov.cn 的「令」页与公报页。
2. 无更新版本 → **P2 判定全部走本地文档**，不再联网检索目录全文。
3. 发现更新版本 → **只问一次**是否把新版重建到 `shared/`（`node scripts/build-catalog.mjs --source <新公报URL> --out <新文件>`）；用户不同意则本次用 `web_search` 取新版全文判定，并标 `W_CATALOG_STALE_LOCAL`。
4. P2 判定调用：

```bash
node scripts/feasibility-rank.mjs catalog --terms "<方向名>,<同义词1>,<同义词2>" [--catalog <文件>] [--json]
```

- `--terms` 至少 2 个词（方向名 + 同义/上位/下位词），少于 2 个直接失败（`E_CATALOG_TERMS_MISSING`）——这是"穷尽检索"的前提。
- 输出：命中明细（`类别/章/子章/条目/命中词`）、`结论 ∈ {鼓励类, 限制类, 淘汰类, 允许类}`、`检索词清单`、`文件 sha256`、`版本`。
- 未命中 → `结论 = 允许类`（目录未列名），并保留检索词清单作为否定结论的证据。
- 命中多个类别 → 以**限制/淘汰优先**（对政策支持度更不利）计，并在备注写明冲突。

### 3.2.1 「建议复核」与允许类的举证责任

目录用词与方向名常常不同（例：方向「氢能储运装备」对应目录鼓励类条目「高密度储氢技术开发应用及设备制造」）。为避免把"用词不同"误判成"目录未列名"：

1. `catalog` 在**未命中**时会额外给出 `建议复核[]`（用检索词的三字子串回撞目录条目，按共同子串数排序，**只作提示、不改变结论**）。
2. 出现「建议复核」时**必须先补检索词重跑**（补同义/上位/下位词，例如用「储氢」「氢能」而不是「氢能储运装备」），直到命中或确认无列名条目。
3. 判 `允许类` 时**必须**在 `政策.目录.复核理由` 写一行复核说明（用了哪些检索词、是否处理了「建议复核」、为何仍判未列名）；缺失 → `E_SCHEMA`。
4. 检索词与最终结论必须写入 `政策.目录.检索词` 与 `政策.目录.命中`，供复核。

### 3.3 P2 置信度（三档）

| 置信度 | 成立条件 |
|--------|---------|
| 高 | 本地文档存在且 `sha256` 记录在案 + `--terms` ≥2 词 + 目录版本与 Step 0.4 结论一致；未命中属"有限固定文本的穷尽否定"，同样可判高 |
| 中 | 版本未确认（`W_CATALOG_VERSION_UNCONFIRMED`）／本地文件缺失退回 `web_search`（`W_CATALOG_MISSING`）／仅 1 个检索词／命中多类需人工裁定 |
| 低 | 目录全文不可得（本地与联网均失败）→ 该关只能存疑 |

## 4. Step 2 的 web_search 协议（产业基金投资事件）

1. 每个方向至少 **2 条不同检索式**：①主体维度（部委/国家级引导基金/省级引导基金/市县级产业基金）+ 方向名 + 时间窗；②金额/事件维度（产业基金 投资 金额 用途 + 方向名 + 时间窗）。
2. 每条检索式必须包含：方向名、主体范围、`近12个月`、要求字段（投资主体、被投对象、投资形式、投资金额、资金用途）。
3. 每条结果记录：`URL`、`标题`、`发布日期`、`发布方`。
4. 只有**政府/基金/公司官方发布或权威媒体**可计入事件来源；其余标 `互联网查询` 且置信度 ≤ 中。
5. 主体范围**排除纯市场化 VC/PE**（不属于"国家部委→省级→市县级产业基金"链路）。
6. 检索词清单与各检索式返回条数必须留痕（用于覆盖率与置信度判定）。
7. 空结果 → 同义措辞重试一次 → 仍空则标 `[数据暂不可用]` + 记 `meta.降级说明[]`，该维度**存疑**（不淘汰）。

### 4.1 归属判定（脚本只校验、不判断）

- 由 LLM 逐条判断 `归属判定 ∈ {属于, 不属于}` 并写 `归属理由`：范围**不得大于方向本身**（不得用上位方向事件充数）。
- 判为 `不属于` 的事件必须进入 `已排除事件[]`（含理由），不得静默丢弃。

## 6. 来源与置信度判定

### 6.1 来源枚举（逐字使用）

| `source.type` | 适用场景 |
|--------------|---------|
| `Wind 结构化数据` | Wind 行情、财务、估值、宏观/行业 EDB 指标 |
| `公司公告` | 公告、定期报告、招股书（原文可核验） |
| `政府文件` | 政府官网政策原文、目录全文、部委发布（含文件号/发布机构/日期） |
| `Wind 新闻检索` | Wind 财经新闻检索结果 |
| `券商研报` | 券商研究报告观点与数据 |
| `互联网查询` | 通用互联网信息、第三方机构测算、转载稿 |

> **与 `santi-1-incremental-rank` 的差异及理由**：santi-1 面向规模测算，对公告/研报一律取「中」；本技能多数证据点是**原文可核验的存在性判定**（扩产公告、新签订单、目录条目），若公告/政府文件原文不能判「高」，企业落地关的硬性条件（要求置信度为高）将永不可达，故把**可核验原文**列为高权威。该差异只影响本技能的置信度表，不改动 santi-1。

### 6.2 三维修正（取**最保守**结论）

| 维度 | 高 | 中 | 低 |
|------|----|----|----|
| 来源权威性 | `Wind 结构化数据` / `公司公告` / `政府文件` | `Wind 新闻检索` / `券商研报` | `互联网查询` |
| 口径匹配 | 与目标口径一致 | 需单位/汇率换算但口径一致 | 口径偏大或偏小 |
| 时效 | 落在声明窗口内 | 超出窗口 ≤1 年 | 超窗口 >1 年或年份不明（`未标注`） |

- 最终 `confidence ∈ {高, 中, 低}`，三维修正过程写入 `confidence_basis`（一行，可核对）。
- **维度置信度 = min(该维度所有必需数据点置信度)**（取最保守）。
- **机械规则**：`source.type == "互联网查询"` 或 `source.detail` 含第三方机构名（QYResearch、TrendForce、弗若斯特沙利文、IDC、GGII 等）时，`confidence` **不得为「高」**；违反 → 自动降为「中」，记 `W_CONFIDENCE_UPGRADED`。

### 6.3 近似口径与向下修正（硬性）

- 近似口径必须同时声明：`precision = "近似"`、`caliber`（实际口径）、`caliber_vs_target ∈ {偏大, 偏小}`、`caliber_note`、`tag = "[待验证]"`；缺一即 `E_APPROX_CALIBER_INCOMPLETE`。
- **禁止用近似口径直接打分**：定性三关里，只有近似口径可用时该子项**按「未命中」计**（向下修正），并把修正逻辑写进备注，记 `W_PROXY_DOWNGRADED`。
  - 例：订单数据取不到，只有「一致预期营业收入同比增速 +35%」→ 订单子项判**未命中**，备注 `订单仅有营业收入一致预期近似口径，已向下修正为未命中`。

### 6.4 汇率与单位

- `config.units` 为每类金额显式声明 `{ unit, currency }`；`unit ∈ {亿元, 亿美元, 万亿元, 万元}`，`currency ∈ {CNY, USD}`，两者必须自洽。
- **内部统一折算为人民币亿元**，换算过程显式留痕到 `meta.单位与汇率`，禁止心算。
- 汇率优先级：① 用户指定 → ② Wind 最新汇率（`economic_data`，来源写 `Wind 结构化数据`）。都取不到时不得换算：该事件/数据点不计入金额、置信度降**低**并记 `W_FX_ASSUMED`。
- 万亿 × 10000 = 亿；万元 ÷ 10000 = 亿；`亿美元 × fx.usdcny = 亿元`。

## 7. Fallback 顺序

```
（Step 1 / Step 3）
financial_docs / stock_data / economic_data 无结果 → 同义措辞重试一次 → web_search 补充
web_search 无结果 → 标 [数据暂不可用] + 记入 meta.降级说明[] → 该维度存疑（不淘汰）
Wind 未就绪 → 输出「未就绪提示语」→ 用户确认后才允许仅用 web_search

（Step 2）
web_search 空 → 同义措辞重试一次 → 标 [数据暂不可用] + 存疑
```

- **禁止**任何层级 fallback 耗尽后虚构数字、机构名、文号、URL 或年份；只能标注缺失并说明对结论的影响。
- 语义判断（归属判定、同义归并、龙头相关性）不改变"淘汰需证据充分"的前提。
