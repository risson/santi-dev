# 每日定时运行契约（单一真源）

> 本文件是**定时运行**的唯一权威定义：三要素问询、双路径创建、模板、诚实边界。
> 默认行为：用户没提"定时/每日/推送"时**不创建任何定时任务**，与 `daily-tech-news` 的推送政策一致。

## 1. 触发与问询顺序

```
用户触发本技能
  → 问一次：一次性运行 / 每日定时运行
      → 一次性：再问锚定日期（今天 / 指定历史日期 D）
          → 今天：直接跑 Step 1–5
          → 历史日期 D：先做回溯锚定（见 Step 0.6），再跑 Step 1–5（结果不写主池）
      → 每日定时：先完成三要素确认（缺哪问哪）→ 复述确认 → 创建任务 → 再跑一次首轮
```

> **回溯与定时互斥**：历史日期不可定时（外部调度器触发的是"当天"）。用户同时要求两者时，
> 如实说明并改为一次性回溯，**不得静默降级**、不得创建"每天回溯同一天"的任务。

### 1.1 三要素（缺一不可，禁止擅自取值）

| 要素 | 问法 | 默认 |
|------|------|------|
| **推送时间** | 「每天几点跑？给 `HH:MM`（24 小时制，Asia/Shanghai）」 | 无默认 |
| **推送内容** | 「产出物放哪？」 | **`{根目录}/生产环境/当前选股池/`**（必须明确告知用户这是默认产出物）；可再加 `{根目录}/生产环境/每日运行记录/<本轮运行目录>/` |
| **推送目标** | 「结果送到哪：对话 / 文件 / 其它渠道？」 | 无默认 |

- 用户指定了与默认不一致的内容 → 以用户为准，并把实际路径复述一遍。
- 推送目标与产出物不一致（例如只要"对话"却要写文件目录）→ **再确认一次**。
- 「其它渠道」（邮件/企业微信/飞书/短信…）：**如实说明当前 harness 没有外发通道**，给出两个可行替代：
  - ① 文件 + 对话摘要（默认推荐）；
  - ② 用户自备外部程序读取 `{选股池目录}/当前选股池.csv` 再自行推送。**不得声称已经推送成功。**

### 1.2 创建前必须复述

> 「将创建每日任务：**每天 HH:MM（Asia/Shanghai）** → 执行一轮三性自动化选股 → 产出写入 **`<路径>`** → 结果投递到 **<目标>**。确认？」

用户确认后才创建；创建结果（成功/失败/降级）写入 `运行清单.json` 的 `调度` 段。

## 2. 双路径

### 路径 A（首选）：会话内定时能力

1. 检查当前环境是否提供定时/提醒类工具（例如 `schedule_create` / `schedule_list`，见工具目录）。
2. **存在** → 创建每日任务：
   - 标题：`三性自动化选股 · 每日选股池更新`；
   - 时间：用户指定（Asia/Shanghai）；
   - 触发内容：`执行 santi-daily-pool-refresh 的一次性运行：产出写入 生产环境/当前选股池/`；
   - 投递：回到本会话（这是该能力唯一的投递语义）。
3. 用 `schedule_list` 复核任务确实存在，并把任务 id 与时间写入运行清单。**不得**未复核就宣称已设置。
4. 若该能力未安装：如实告知，并给出安装路径——`@deepseek-ai/dsh-experimental-schedule-bundle`（经 `plugin_manager` 安装后需重启 profile 才生效），然后走路径 B。

### 路径 B（降级）：外部调度器

生成配置（不改系统状态）：

```bash
node {技能目录}/scripts/santi-daily-pool.mjs schedule \
  --time "HH:MM" --date-skill "santi-daily-pool-refresh" \
  --root "{根目录}" --channel file \
  --out "{根目录}/生产环境/每日运行记录/调度配置.md"
```

脚本会输出 crontab / systemd user timer / Windows 任务计划三套模板（见该命令输出与 `调度配置.md`）。
**默认只打印 + 写 `调度配置.md`，不修改系统 crontab 或计划任务**；用户明确要求代为安装时，才在取得同意后执行，并复核结果。

## 3. 诚实边界（必须向用户说清）

| 事实 | 说明 |
|------|------|
| 外部调度器里没有会话 | crontab/systemd/schtasks 拉起的是**无会话进程**；它们只能执行外部触发命令，不能"让 AI 自己思考"。 |
| 本技能的流水线需要 agent | Step 2 的事件分析、三性 pk 的取数都需要 agent 会话。因此外部调度的触发命令必须是当前环境可用的 headless 入口；**拿不到可用入口时，如实告知"需每日手动触发"**。 |
| 投递语义有限 | 会话内定时能力的投递目标是**原会话**；外部渠道（邮件/IM）没有内置通道。 |
| 效果等同的替代 | 用户每天手动触发一次本技能，效果与定时一致（除时间点外）。 |

**禁止**：伪造"已设置定时任务"、伪造"已推送"、把 `调度配置.md` 的存在说成任务已生效。

## 4. 每次运行的独立性

- 每一轮运行都是**自包含**的：靠 `运行清单.json` 与 `{选股池文件}` 承接状态，不依赖上一轮的会话上下文。
- 定时任务触发时，若发现 `{选股池文件}` 不存在或为空 → 按"首次运行"处理（A 为空），不阻断。
- 若同一时间点已有一轮在跑：以 `{本轮运行目录}` 的分钟级时间戳区分，两轮互不覆盖；后跑的一轮以主文件当时的实际内容为基准合并（`merge-pool` 幂等）。
- **回溯轮的 A 基准是快照**（`asof-pool` 判定），与主池当时的内容无关；回溯轮也不回写主池，
  因此可与常规轮次并行/交叉执行而不产生写冲突（运行目录用 `{D}-回溯-{HH}-{MM}` 区分）。
- 定时任务永远按「今天」锚定运行；回溯只能由用户一次性触发。

## 5. 验收清单

```
□ 是否只问了模式一次？定时三要素是否全部明确（未擅自取值）？
□ 是否复述了「时间/内容/目标/时区」并取得确认？
□ 任务创建后是否用列表接口复核，并把 id/时间写入运行清单？
□ 环境不支持时，是否如实说明并给出外部调度或手动触发的替代方案（未谎报）？
□ 是否只打印/写 调度配置.md，未在未授权时修改系统 crontab 或计划任务？
□ 首轮运行是否真的跑了一次（定时模式也要有本轮产物）？
□ 若用户要求「回溯 + 定时」：是否如实说明不支持并改为一次性（未伪造定时回溯任务）？
```
