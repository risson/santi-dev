# 输入契约与校验

## 0. 方向参数

输入契约本身**方向无关**：同一份上游 JSON 既能跑利好档也能跑利空档，由 `--direction bullish|bearish`
（缺省 `bullish`；也接受 `利好`/`利空`）决定保留哪一侧：

| 方向 | 保留 | 排除 |
|------|------|------|
| `bullish` / 利好 | `影响方向 = 利好` 且 `推理置信度 = 高` | `中性`、`利空`、置信度 `中/低` |
| `bearish` / 利空 | `影响方向 = 利空` 且 `推理置信度 = 高` | `中性`、`利好`、置信度 `中/低` |

非法 `--direction` → `E_USAGE`（退出码 2），不产出文件。判定细节见 `ranking-rules.md`。

## 1. 定位

本技能消费的 JSON 由上游技能 `event-chain-navigator` 产出。附件样本
`event-chain-navigator_新型电池产业十五五规划_2026-09-28.json` 即该契约的实例。

文件命名约定：`<上游技能名>_<事件简称>_<YYYY-MM-DD>.json`。

## 2. 通用化固定格式

```jsonc
{
  "meta": {
    "generated_at": "YYYY-MM-DDTHH:MM:SS+08:00",
    "数据源": ["wind-mcp-skill", "web_search"],
    "输出形态": "json",
    "降级说明": []
  },
  "事件": {
    "事件标题": "≤40字",
    "事件总结": "≤60字",
    "事件日期": "YYYY-MM-DD 或 未标注",
    "日期来源": "Wind 金融终端 | 公司公告 | 新闻搜索 | 互联网查询 | 券商研报 | 未标注"
  },
  "影响环节": [ /* 见下表，允许为空数组 */ ],
  "disclaimer": "……"
}
```

## 3. 字段表

| 层级 | 字段 | 必需 | 枚举 / 规则 | 本技能用途 |
|------|------|------|------------|-----------|
| 顶层 | `meta` | 是 | 对象 | 不参与判定 |
| 顶层 | `meta.generated_at` | 否 | ISO 8601 | 仅在结果 `meta` 中透传参考 |
| 顶层 | `事件` | 是 | 对象 | `事件日期` 用于 `证据日期` |
| 顶层 | `事件.事件日期` | 否 | `YYYY-MM-DD` \| `未标注` | `证据日期` 兜底 |
| 顶层 | `影响环节` | **是** | 数组，允许为空 | **筛选对象**；缺失 → 跳过该文件 |
| 条目 | `细分产业方向` | **是** | ≤20 字，不含公司名 | 同义词归并的唯一对象 |
| 条目 | `影响方向` | **是** | `利好` \| `利空` \| `中性` | §1/§2 判定 |
| 条目 | `影响定级` | **是** | `S级` \| `A级` \| `B级` \| `C级` | §1/§3 判定 |
| 条目 | `传导强度` | **是** | 6 值枚举（见 ranking-rules §0） | §1/§3 判定 |
| 条目 | `推理置信度` | **是** | `高` \| `中` \| `低` | §1/§2/§3 判定 |
| 条目 | `产业链层级` | 否 | 四层枚举 | 仅透传参考，不参与判定 |
| 条目 | `传导逻辑` | 否 | ≤30 字 | 不参与判定 |
| 条目 | `产业阶段` | 否 | 五值枚举 | 不参与判定 |
| 条目 | `关键验证点` | 否 | ≤40 字 | 不参与判定 |
| 条目 | `来源标注` | 否 | 字符串数组 | 不参与判定 |
| 条目 | `证伪点` | 否 | 对象数组 | 不参与判定 |
| 条目 | `事件标题` / `事件总结` / `事件日期` | 否 | 同顶层 | **条目级覆盖**，`事件日期` 优先于顶层用于 `证据日期` |

## 4. 多事件输入

上游在多事件场景下会在条目内覆盖 `事件标题 / 事件总结 / 事件日期`。
本技能一并处理：`证据日期` 取 `条目.事件日期 ?? 顶层.事件.事件日期`，因此不同来源文件/条目可携带不同事件日期。

## 5. 容错与校验

| 情况 | 错误码 | 行为 |
|------|--------|------|
| 输入路径不存在 | `E_INPUT_NOT_FOUND` | 退出 2 |
| 目录内无 `*.json` | `E_NO_INPUT_FILES` | 退出 1，不产出文件 |
| JSON 解析失败 | `E_JSON_PARSE` | **跳过该文件**，计入 `meta.跳过的文件[]`；全部失败 → 退出 1 |
| 顶层非对象 / 无 `影响环节` 数组 | `E_MISSING_IMPACT_ARRAY` | 跳过该文件，同上 |
| 条目缺必需枚举字段 | `W_MISSING_FIELD` | 按 ranking-rules §4 处理，留痕，不静默入选 |
| 枚举措写变体（`一级/高`、`s级`） | —— | §0 规范化后正常判定 |
| 枚举值不在允许集合（如 `D级`） | `W_UNCLASSIFIED_ROW` | 按 ranking-rules §3 第 12 行落"低"（仅方向与置信度都合规时） |
| `影响方向` 为另一方向（利好档遇利空 / 利空档遇利好） | `D1_NOT_BULLISH` / `D1_NOT_BEARISH` | 排除，不落「低」档 |

**扫描约定**：目录默认取 `.json`（非递归），`--recursive` 递归；跳过隐藏文件（以 `.` 开头）与 0 字节文件。
