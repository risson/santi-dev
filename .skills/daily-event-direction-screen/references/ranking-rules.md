# 判定规则（单一真源）

> 本文件是筛选、分级、聚合、排序的**唯一权威定义**。`scripts/screen.mjs` 中的常量与判定分支必须与本文件逐行一致；
> 若二者出现分歧，以本文件为准并同步修脚本。SKILL.md 只引用，不复写规则。
>
> **方向**由 `--direction bullish|bearish` 选择（缺省 `bullish`）。两个方向**共用** §0 归一化、§3 优先级阶梯、
> §4 缺字段、§5 去重、§6 聚合、§7 排序；只有 §1 的「反向硬排除」与 §2 的「方向门禁」按方向切换。
> §1–§2 中标注「利好档」的行即 1.0.0 的原始行为，逐字节不变。

## 0. 枚举规范化

判定永远基于**规范化后的值**，但输出的 `剔除清单` 保留原始文本。

| 字段 | 规范化 | 允许的原值写法 | 规范值 |
|------|--------|---------------|--------|
| `影响方向` | 去空格/全角空格 | `利好`、`利空`、`中性` | 同左 |
| `影响定级` | 去空格，`级` 可省，大小写不敏感 | `S`、`S级`、`s级`；同理 A/B/C | `S` \| `A` \| `B` \| `C` |
| `传导强度` | 删除 `传导` 二字；分隔符 `/`、`／`、`|` 等价；空格删除 | `一级传导/高`、`一级/高`、`一级／高` | `一级/高` 等 6 值 |
| `推理置信度` | 去空格 | `高`、`中`、`低` | 同左 |

`传导强度` 的 6 个规范值及其二元组：

| 规范值 | 级序 level | 强度 strength |
|--------|-----------|--------------|
| `一级/高` | 1 | 3 |
| `一级/中` | 1 | 2 |
| `一级/低` | 1 | 1 |
| `二级/高` | 2 | 3 |
| `二级/中` | 2 | 2 |
| `二级/低` | 2 | 1 |

- `级序` 解析接受 `一`/`二` 或 `1`/`2`；`强度` 接受 `高`/`中`/`低`。
- 无法解析为上述 6 值之一 → 视为 `null`（不可分类），按 §4 处理。

### 0.1 方向 profile（唯一差异面）

| 轴 | `--direction bullish`（利好档，缺省） | `--direction bearish`（利空档） |
|----|--------------------------------------|--------------------------------|
| 保留方向 | `影响方向 = 利好` | `影响方向 = 利空` |
| 反向硬排除 | §1 的 `R2` / `R3`（针对利空强项） | **无**：利好强项由 §2 的 `D1_NOT_BEARISH` 覆盖 |
| 方向门禁原因码 | `D1_NOT_BULLISH` | `D1_NOT_BEARISH` |
| 置信度门禁 | 只保留 `推理置信度 = 高` | 只保留 `推理置信度 = 高` |
| 优先级阶梯 | §3 的 11 行阶梯 | **同一张表**（逐行相同） |
| 默认输出目录 | `<输入>/../event-direction-rank-bullish/` | `<输入>/../event-direction-rank-bearish/` |
| 输出文件名前缀 | `event-direction-rank-bullish` | `event-direction-rank-bearish` |
| 输出顶层 `方向口径` | `"利好"` | `"利空"` |

`--direction` 同时接受中文取值 `利好` / `利空`；缺省 `bullish`；非法取值 → `E_USAGE`（退出码 2），不产出任何文件。

## 1. 第 1 层：排除（命中任一即丢弃，记录原因码）

| 原因码 | 条件 | 适用范围 |
|--------|------|---------|
| `R1_LOW_CONFIDENCE` | `推理置信度 = 低` | 两个方向共有 |
| `R2_BEARISH_S_HIGH` | `影响方向 = 利空` **且** `影响定级 = S` **且** `推理置信度 = 高`（不限传导强度） | 仅利好档 |
| `R3_BEARISH_A_L1_HIGH` | `影响方向 = 利空` **且** `影响定级 = A` **且** `传导强度 = 一级/高` **且** `推理置信度 = 高` | 仅利好档 |

判定顺序：`R1` → `R2` → `R3`（利好档）或 `R1`（利空档，无 R2/R3），命中即停（一条只记一个原因码）。

> **利空档为何没有 R2/R3 的镜像码**：`R2`/`R3` 的语义是「利好档里对最强利空项做硬排除」。利空档下，
> 「利好 S+高」「利好 A+一级高+高」本来就**不属于本档要保留的方向**，已被 §2 的 `D1_NOT_BEARISH` 完整覆盖。
> 再设两个镜像码只增加原因码表面积、不增加任何信息，故不设；这不是遗漏。

## 2. 第 2 层：方向/置信度门禁

| 原因码 | 条件 | 适用范围 |
|--------|------|---------|
| `D1_NOT_BULLISH` | `影响方向 ≠ 利好`（含 `中性`、残留 `利空`、方向缺失） | 仅利好档 |
| `D1_NOT_BEARISH` | `影响方向 ≠ 利空`（含 `中性`、`利好`、方向缺失） | 仅利空档 |
| `D2_CONFIDENCE_NOT_HIGH` | `推理置信度 ≠ 高`（即 `中`，或置信度缺失） | 两个方向共有 |

判定顺序：`D1` → `D2`，命中即停。二者均在 §1 之后判定。

> 设计口径（已与用户确认）：**利好档只让「利好 + 推理置信度 高」进入分级；利空档只让「利空 + 推理置信度 高」进入分级。**
> `中性`、方向相反、`推理置信度 中` 一律排除出结果，**不进入「低」档**。

## 3. 第 3 层：优先级阶梯（两个方向共用同一张表）

行序即优先级，**自上而下命中即停**。方向不参与本表判定。

| # | 影响定级 | 传导强度 | 推理置信度 | 优先级 |
|---|---------|---------|-----------|--------|
| 1 | S | 一级/高 | 高 | **最高** |
| 2 | S | 一级/中 | 高 | **非常高** |
| 3 | S | 二级/高 | 高 | **非常高** |
| 4 | S | 二级/中 | 高 | **高** |
| 5 | A | 一级/高 | 高 | **高** |
| 6 | A | 一级/中 | 高 | **中高** |
| 7 | A | 二级/高 | 高 | **中高** |
| 8 | A | 二级/中 | 高 | **中** |
| 9 | B | 一级/高 | 高 | **中** |
| 10 | B | 一级/中 | 高 | **中低** |
| 11 | B | 二级/高 | 高 | **中低** |
| — | 其余（`B/二级/中`、`C级` 任意强度、传导强度含「低」、传导强度不可解析） | | | **低**，并计 `W_UNCLASSIFIED_ROW` |

说明：

- 第 11 行**必须**在 `B/二级/中` 之前命中不到任何行时才落到「低」——因为规则链未枚举 `B/二级/中`，它按文案属于"其余"。
- `S/一级/低`、`S/二级/低`、`A/*/低` 等虽方向与置信度合规，但不在 3 行枚举内，按第 12 行落"低"。
- 方向合规、`推理置信度 高`，但 `影响定级` 无法解析（如 `D级`）→ 落"低" + `W_UNCLASSIFIED_ROW`（不静默丢弃）。

### 3.1 利空档用户口径 ↔ 本阶梯行对照

用户给出的 6 条利空分级条件，拆开 `or` 后与上表**逐行一一对应**（这是两个方向可以共用一张表、共用一个脚本的依据）：

| 用户条件（利空 + 推理置信度:高） | 对应行 | 优先级 |
|---|---|---|
| S + 一级/高 | 1 | 最高 |
| S + 一级/中；S + 二级/高 | 2、3 | 非常高 |
| S + 二级/中；A + 一级/高 | 4、5 | 高 |
| A + 一级/中；A + 二级/高 | 6、7 | 中高 |
| A + 二级/中；B + 一级/高 | 8、9 | 中 |
| B + 一级/中；B + 二级/高 | 10、11 | 中低 |
| 其余 | 第 12 行 | 低 |

## 4. 缺字段与不可分类

| 情况 | 处理 | 记录 |
|------|------|------|
| 缺 `影响方向` | 无法归入本档方向 → 按 `D1`（`D1_NOT_BULLISH` / `D1_NOT_BEARISH`）排除 | `W_MISSING_FIELD` |
| 缺 `影响定级` 或 `传导强度`，但方向合规、`推理置信度=高` | 落"低"档保留 | `W_MISSING_FIELD` + `W_UNCLASSIFIED_ROW` |
| 缺 `推理置信度` | 不能确认"高" → 按 `D2_CONFIDENCE_NOT_HIGH` 排除 | `W_MISSING_FIELD` |
| 缺 `细分产业方向` 或为空串 | 整条丢弃 | `W_MISSING_FIELD`，原因码 `E_SKIPPED_ENTRY` |
| `影响方向` 为相反方向、`推理置信度=高`、`影响定级=B/C` | 不在排除规则内；但方向不符合本档 → `D1` 排除 | —— |

原则：**绝不静默入选**。任何无法按 §3 明确归级的条目，要么明确排除，要么落"低"并留痕。

## 5. 去重

按指纹 `标准名 + 影响方向 + 影响定级 + 传导强度 + 推理置信度` 去重，保留首条，计入 `W_DUPLICATE_DROPPED`。

原因：同一条目重复出现会直接放大该方向的档位计数，必须在聚合前消除。
指纹含 `影响方向`，因此同一标准名下的利好条目与利空条目**不会互相去重**；同一次运行只处理一个方向。

## 6. 聚合

按**标准名**（同义词归并后的名字）分组：

- 七档计数各自累加，缺省 `0`；
- `来源条目数` = 合并前（去重后）条目总数；
- `来源文件数` = 去重后的来源文件数；
- `证据日期` = 该组所有条目 `事件日期`（条目级优先于顶层）的日期集合，`未标注` 剔除后升序去重。

同义词词典**跨方向共用**（见 `dictionary-format.md`）：利好轮次沉淀的标准名/别名，利空轮次直接命中。

## 7. 排序

比较链（档位由高到低，与"数量多者优先"方向一致）：

```
比较链 = [最高, 非常高, 高, 中高, 中, 中低, 低]
```

每个方向构成 7 元组 `(c最高, c非常高, c高, c中高, c中, c中低, c低)`：

1. 按元组**逐位降序**比较（即先比"最高"数量；相同再比"非常高"数量；依次类推）；
2. 7 元组完全相等时，按标准名字典序**升序**（确定性兜底，保证同输入同输出）。

> 该实现即用户 5.1–5.3 的"按优先级统计数量排序"：档位优先级高者先比，数量多者靠前；不是加权打分，也不看 `最高` 的占比。
> 排序链与方向无关，两个方向共用。
