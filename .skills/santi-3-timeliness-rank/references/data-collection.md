# 取数与取证规范（单一真源）

本文件定义 `SKILL.md` Step 1–Step 3 的**全部取数、取证与降级动作**：工具路由、检索式写法、来源类型枚举、
置信度判定。`SKILL.md` 与 `references/ranking-rules.md` 只引用本文件，不复写细节。

**总原则**：任何数字、机构名、年份、URL 都必须来自工具回执；取不到写 `[数据暂不可用]` 并记入
`meta.降级说明[]`。**绝对禁止**用估计值、常识值或"约"填充。

---

## 0. 取数前依赖体检（门禁）

Step 1 与 Step 2 需要 `wind-mcp-skill`（Step 3 的现场补取也需要）；Step 2 若用户已给文件集合则不联网。

```yaml
wind_probe:
  # 只在 wind-mcp-skill 目录内发一次探针，不批量刷
  server_type: metadata
  tool: list_tools
  params: {}
```

| # | 检查项 | 通过标准 | 不通过 |
|---|--------|---------|--------|
| W1 | `wind-mcp-skill` 技能目录与 `SKILL.md` 可读 | 可读 | 输出未就绪提示语，`wind_available = false` |
| W2 | 入口 CLI 存在 | 该技能 `SKILL.md` 指定的入口存在（官方版通常为 `scripts/cli.mjs`） | 同上 |
| W3 | `node` 可用 | `node --version` 正常 | 同上 |
| W4 | 密钥/额度有效 | 探针收到数据对象（非错误信封） | `AUTH_ERROR`/`SETUP_ERROR` → `false`；`RATE_LIMIT_ERROR` → **不判未就绪**，记降级并改串行 |

**未就绪提示语**（逐字复用）：

## 1. Step 1：主叙事时效取证

### 1.1 目标

对每个细分方向回答两件事：

1. **主叙事逻辑**：该方向本身或其所在产业链，最主要的叙事是什么（≤40 字）？
2. **落地时间档位**：这个叙事"落地"（国产替代率 >50%、政策规划目标达成、GWh 级大规模量产、商业化普及等）
   大概在多久以后？落入 `短期（1-2年）` / `中期（3-5年）` / `长期（5年以上）` / `未标注`。

### 1.2 工具路由

| 要素 | 首选 | 兜底 |
|------|------|------|
| 政策/规划目标与时间表 | `web_search`（只认 gov.cn / ndrc.gov.cn / miit.gov.cn 等官方发布页与公报） | `financial_docs.get_financial_news` |
| 产业进展与量产/商业化节奏 | `financial_docs.get_financial_news`（主题含方向名 + 量产/中试/招标/投产） | `web_search`（权威媒体） |
| 机构对产业化时间的判断 | `web_search`（券商研报口径，必须标 `[待验证]`） | — |
| 所在产业链归属 | 由 LLM 直接推理（行业常识），必要时 `financial_docs` 交叉验证 | — |

### 1.3 来源类型枚举（`主叙事.source.type`）

| 取值 | 含义 | 置信度上限 |
|------|------|-----------|
| `政府文件` | 国家部委/国务院发布的规划、目录、行动方案 | `高` |
| `Wind 金融终端` | Wind 结构化数据/新闻检索回执 | `高` |
| `公司公告` | 上市公司公告 | `高` |
| `新闻搜索` | 权威媒体报道 | `中` |
| `互联网查询` | 一般网页、百科、第三方站点 | `中` |
| `券商研报` | 券商研报口径（`financial_docs` **不含**研报全文，须走 `web_search`） | `中` |

- 来源被标「高」但类型属于后三类（`新闻搜索`/`互联网查询`/`券商研报`，或 detail 含"测算/第三方/机构预测"）
  → 脚本自动降为「中」并记 `W_CONFIDENCE_UPGRADED`（见 `ranking-rules.md`）。
- 取不到任何依据 → `落地时间档位 = 未标注`、`confidence = 低`，记 `W_NARRATIVE_UNRESOLVED`（**不淘汰**）。

### 1.4 落地判据必须可观测

`落地判据` 必须是**可核验的事件或指标**，不得写"行业景气度提升"这类不可观测表述。合格示例：

- `国产替代率 >50%`、`政策规划目标年份到期`
- `GWh 级量产线投产并达到设计良率`
- `示范堆并网发电`、`头部客户批量认证通过`

### 1.5 硬约束

1. **时间范围必须显式**（禁止裸查询）：`截至最新年度的…` / `近 3 年的…` / `2026-2030 年的…` / `2026 年全年的…`。
2. **单条查询 ≤ 6 指标 + 条件内嵌**：如 `"{方向} 量产时间表、主要厂商、产能规划"`；
   **禁止**"先查全行业再本地筛选"。
3. **每方向 ≥1 条主叙事检索 + ≥1 条落地时间校验检索**，两次检索的检索词写入 `备注` 或证据附录。
4. 档位判断必须能回答"**为什么不是更近/更远的那一档**"，在证据附录里留一行理由。

## 2. Step 2：市场规模与产业链层级（未给文件集合时重取）

用户给出声明用于"产业链瓶颈环节和产品属性识别"的文件集合时，**直接走脚本 `extract`**，不联网。

未给文件集合时按下表重取，并把结果整理成 `extract` 可读的形态（或直接写入 `inventory.json`）：

| 要素 | 首选 | 兜底 |
|------|------|------|
| 预测 3-5 年市场规模 | `financial_docs.get_financial_news`（`"{方向} 行业 3-5 年市场规模 预测 亿元"`） | `web_search`（第三方机构测算，必须标 `[待验证]`） |
| 机构测算年份与口径 | 同上（detail 必须写"机构 + 报告年份 + 口径"） | 同上 |
| 产业链层级 | 由 LLM 按四层枚举判定（`上游原材料/耗材` / `上游核心零部件/设备` / `中游制造/集成` / `下游应用`） | 用 event-chain-navigator 输出文件交叉验证 |

- 单位与汇率：金额必须带 `原值` + `原单位 ∈ {亿元, 万元, 万亿元, 亿美元}` + `currency`；
  **美元金额必须**给 `config.fx.usdcny`（优先用户指定值，否则取 Wind 最新汇率并写 `fx.source` / `fx.as_of`）。
- 第三方测算必须 `precision = "近似"` + `caliber` + `caliber_vs_target ∈ {偏大, 偏小}` + `caliber_note` + `tag = "[待验证]"`，
  缺任一直接 `E_APPROX_CALIBER_INCOMPLETE`。
- 取不到 → `预测3-5年市场规模 = null`，档位记 `未标注`，记 `W_MARKET_UNRESOLVED`，**保留不淘汰**。

## 3. Step 3：事件驱动时效（文件集合与补取）

### 3.1 用户已给文件集合（常规路径）

文件集合应声明用于「事件驱动时效识别」，内容为 `daily-event-direction-screen` 的结果 JSON
（含 `细分产业方向[].排序逻辑`）或其原始 `影响环节[]`。直接走脚本 `aggregate`，不联网。

### 3.2 用户未给文件集合（按用户确认的兜底）

1. **先问一次**是否补取；用户拒绝 → 全部方向事件列计 `0` + `W_NO_EVENT_EVIDENCE`，继续出表。
2. 用户同意 → 窗口默认**近 90 天**（起止写入 `meta.窗口.事件`），逐方向执行：

| 要素 | 首选 | 兜底 |
|------|------|------|
| 近期事件与影响 | `financial_docs.get_financial_news`（`"{方向} 订单 中标 政策 事件 近90天"`） | `web_search` |
| 事件定级/传导强度 | 由 LLM 按 `references/ranking-rules.md` §3.2–§3.4 现场分级 | — |

3. 现场分级后的条目按 §3.3 排除，保留者写入 `事件驱动.排序逻辑`（七档计数），
   并把 `{方向, 事件, 影响定级, 传导强度, 推理置信度, 来源}` 逐条写入证据附录。
4. 现场分级必须**逐条留痕**，不得只给汇总数字；`来源` 必须是工具回执里的 URL/标题/日期。

### 3.3 与上游的一致性

`references/ranking-rules.md` §3.2–§3.5 的枚举规范化、逐层排除（R1–R3 / D1–D2）、优先级阶梯、
指纹去重，与 `daily-event-direction-screen/references/ranking-rules.md` **逐行一致**。
上游规则变更时必须同步本文件与脚本 `judgeImpactEntry()`。

## 4. 置信度判定（统一口径）

| 置信度 | 判定标准 |
|--------|---------|
| `高` | 来源为 `政府文件` / `Wind 金融终端` / `公司公告`；口径与目标一致；年份明确；结论由 ≥2 个独立来源相互印证（或单源为权威原始发布） |
| `中` | 来源为 `新闻搜索` / `互联网查询` / `券商研报`；或口径为近似（偏大/偏小）；或仅单源 |
| `低` | 无可用来源、来源与目标口径明显不匹配、或检索全部返回空 |

**三维修正**：来源权威性 → 口径匹配度 → 时效（取最新）。取三者中最低值作为该数据点置信度，
并在 `confidence_basis` / 证据附录写一行修正过程。

---

## 5. 降级顺序与留痕

1. 首选工具 → 同义措辞重试一次 → 次选工具 → 仍失败标 `[数据暂不可用]`。
2. 每次降级都往 `meta.降级说明[]` 追加 `{ dimension, source, reason }`（`dimension` ∈
   `主叙事时效` / `市场规模` / `产业链层级` / `事件驱动`）。
3. 降级后的置信度上限：`web_search` 第三方测算 → `中`；无来源 → `低`。
4. **降级不等于淘汰**：数据缺失的方向一律保留，只在档位/排序上排末并标 `[待验证]`。
