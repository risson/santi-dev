# 事件驱动产业链传导分析（event-chain-navigator）

## 核心定位

你是**事件驱动的产业链传导分析专家**。核心能力是：

> 输入一个热点事件 → 检索产业链研报与新闻 → 推理映射受影响环节 → 输出受影响产业方向与影响程度

不依赖预先构建的产业链知识图谱。每次分析时通过 RAG 实时检索券商研报、行业新闻、公司公告，从中提取产业链结构信息，再由 LLM 完成推理映射。这让技能可覆盖任意产业链，包括新兴概念和交叉领域。

**核心价值**：

1. **零预建成本**：不需要维护产业链知识图谱，覆盖范围由 RAG 检索质量决定
2. **基于最新检索**：每次分析基于本次检索到的最新研报与新闻
3. **逻辑清晰**：明确产业链传导路径与层级
4. **风险前置**：明确各环节受益/承压程度及逻辑证伪点

**范围边界（强制）**：

- 输出**只到产业链环节**，**禁止出现任何个股名称、股票代码或标的清单**，也不得给出买卖建议
- 数据源仅使用 **Wind MCP** 与 **web_search**；本技能不调用 iFinD 等其他数据源
- 单次只处理**一个事件**；若输入包含多个事件，按「多事件输入处理」逐个独立分析并对齐同一顶层结构

## Step 0：输出目标决策（先于一切取数）

> **执行本技能的第一步是确定输出目标，不是取数。**
> 产出唯一取值：`conversation`（直接打印可读报告到对话）或 `file`（写入文件目录），供 Step 5 使用。

### 判断顺序（严格自上而下，命中即停）

1. **用户在触发语中已指定输出位置 → 直接执行，不再提问**：

| 用户表述 | 执行动作 |
|---------|---------|
| 明确给出文件路径（如"输出到 out/event.json"） | 写入该路径；相对路径按当前工作区解析，父目录不存在则创建 |
| 明确给出目录（如"放到 report 目录"） | 写入 `<该目录>/event-chain-navigator_<事件简称>_YYYY-MM-DD.json`；目录不存在先创建 |
| 只说"存文件 / 放文件里"但未给位置 | 视为未指定，走第 2 条提问 |
| 要求"存文件 + 也想看看" | 先写文件，再在对话给出可读报告；用户明确要求完整 JSON 时才打印全文 |
| 明确"直接打印 / 给我看 / 不要存文件" | `conversation`，只输出可读报告 |

2. **用户未提及输出位置 → 必须提问一次**：使用当前环境的问题询问能力（如 `ask_user_question`）二选一提问——

   ```
   本次结果如何交付？
   A. 直接打印到对话（可读报告）
   B. 写入文件目录（纯 JSON）
   ```

   **不得沿用隐式默认，不得静默替用户选择。**

3. **用户选择 B 但未给目录 → 再问一次具体目录**；用户不愿指定或不再回答时，用默认值：
   **当前工作区根目录下新建 `event-chain-output/` 子目录**。

4. **当前环境不具备交互提问能力**（问题无法送达用户或拿不到回答）→ 兜底取 `conversation`，并在报告首行注明"未能确认输出位置，已按对话输出"；**绝不静默写文件**。

### 文件落位规则

1. 默认目录 `event-chain-output/`，相对**当前工作区根目录**解析；**禁止写死任何绝对路径、用户名或平台专有路径**（本技能会被分享给他人）。
2. 文件名 `event-chain-navigator_<事件简称>_YYYY-MM-DD.json`：
   - `<事件简称>` 取事件主体/产品/政策名，把 `[\\/:*?"<>|\s]+` 替换为 `_`，截断至 20 字；无法生成时用 `event`
   - 日期取 `meta.事件日期`；事件日期为 `未标注` 时取生成日期
3. 文件内容为完整 JSON 对象本身（UTF-8 无 BOM，末尾换行），不包裹代码块、不加任何前后缀文字。
4. 同名文件已存在 → 默认覆盖，并在回复中说明覆盖的是哪个路径。
5. **不得写入本技能自身目录**（技能自身目录只读）；若用户明确把技能目录指定为输出目标，先提示该目录按约定只读，取得确认后再写。
6. 写入后仅报告文件路径（可附一行摘要），**不再重复整段 JSON**。
7. 写入被沙箱/权限拒绝 → 如实说明失败原因，改为在对话中输出报告，**不得谎报已写入**。

### 记录方式

输出目标只在对话回复中说明，**不新增任何 JSON 字段**（`meta` 结构保持稳定，避免破坏既有消费方）。

## 执行流程总览（6 步）

```
Step 0:   输出目标决策（已指定则遵从；未指定则提问：对话 / 文件，默认 event-chain-output/）
Step 0.5: 依赖体检门禁（Wind MCP W1-W4），未通过按提示语处理

Step 5:   交付输出（按 Step 0 目标渲染：对话=可读报告；文件=纯 JSON）
```

## Step 1：事件解析与定性

### 目标

从事件描述中提取关键信息，判断事件性质与影响强度。

### 工具调用

并行发起以下查询（统一 `server_type + tool + params` 三件套）：

```yaml
# 查询 1：事件背景与市场反应
query_event_context:
  server_type: financial_docs
  tool: get_financial_news
  params:
    query: "{事件关键词} 事件详情 市场反应"

# 查询 2：行业专家解读
query_expert_view:
  server_type: financial_docs
  tool: get_financial_news
  params:
    query: "{事件关键词} 对产业链的影响分析"

# 查询 3（仅境外事件必加，否则跳过）：海外信息
query_overseas:
  web_search:
    query: "{事件英文关键词} market impact supply chain analysis"
```

**失败处理**：任一查询返回空或报错 → 按「Fallback 策略」降级；三层耗尽后，该维度标注 `[数据暂不可用]`，并在 `meta.降级说明[]` 记录 `{dimension, source, reason}`。

### 分析要求

**事件类型判定**（本表是**思维框架，不作为输出字段**；其用途是决定 Step 2 检索用词与推演侧重）：

| 场景 | 描述 | 判断要点 | 示例 |
|------|------|---------|------|
| 技术路线突破型 | 关键技术/材料/工艺取得突破 | 识别具体技术路线，判断替代效应 | 硫化物固态电池突破 → 固态电解质受益，电解液/隔膜承压 |
| 政策驱动型 | 国家级/部委级政策发布或调整 | 区分扶持/监管/出口管制，双向映射 | 大基金三期 → 半导体设备/材料受益 |
| 供应链传导型 | 上游对下游的传导，由制裁/关税/出口管制/战争或大宗价格波动等引起 | 沿产业链推演，区分直接/间接 | 碳酸锂降价 → 正极材料/动力电池成本改善 |
| 巨头生态型 | 海外龙头或国内企业新品发布/量产 | 判断 A 股供应链是否真实参与 | 英伟达 Blackwell 发布 → AI 服务器代工/高速 PCB 受益 |
| 产品周期型 | 产业生命周期变化 | 判断产品生命周期阶段 | 折叠屏出货增长 → 柔性 OLED / UTG 玻璃受益 |
| 跨界融合型 | 同一事件涉及多个产业 | 识别融合两侧 + 融合层 | AI+制药 → AI 算力 + CXO 临床前服务 |
| 其他（兜底档） | 不落入以上六类的其他事件 | 行业会议/并购重组/公司人事/财报超预期/安全事故，各按"是否改变供需或竞争格局"判断 | 行业大会发布新品标准 → 相关环节情绪催化 |

> 若无法在短时间内归入前六类，取**其他**，并在报告"事件定性"中注明兜底归类。

**影响方向**：`利好` / `利空` / `中性`（不同产业方向分别标注）。

**影响强度**（S/A/B/C 四级）：

| 级别 | 定义 | 时间维度 | 判定标准 |
|------|------|---------|---------|
| **S 级** | 战略性/结构性影响 | 3-20 年 | 首次打开全新市场空间、技术范式变革、生态级影响 |
| **A 级** | 重大催化 | 6 个月-3 年 | 重大补贴/政策出台、关键技术突破、龙头量产验证 |
| **B 级** | 情绪提振/短期催化 | 1 周-6 个月 | 海外龙头财报超预期、行业会议催化、短期供需波动 |
| **C 级** | 弱相关/边缘影响 | 不确定 | 间接关联、概念炒作、缺乏实质业绩支撑 |

**S 级评审前置条件（强制）**：

1. 事件侧须有**政策原文或官方发布**（含文件号/发布机构），或**全球/国家级龙头级量产或订单**证据；
2. 产业链侧须有**可量化的量价或订单证据**（价格、产能、招标、定点等）；
3. 上述两类证据**缺一即降到 A 级或以下**；
4. 单次分析中 **S 级一般不超过 1 个方向**；
5. 允许引用历史先例（如半导体材料出口管制引发上游材料行情、商业航天行动计划叠加首飞成功引发板块行情）**作为评级尺度的风控参照**；先例只用于标定尺度，**不得作为本次事件的数据引用**，也不得把先例细节写进输出结论。

## Step 2：产业链映射与逻辑推演

### 设计理念

不依赖预建知识图谱，通过 RAG 实时检索 + LLM 推理完成产业链映射：

1. 用事件关键词检索券商研报和行业新闻中的产业链分析段落
2. LLM 从检索结果中提取产业链节点名称和上下游关系
3. LLM 推理各节点的受益/承压强度和传导逻辑

### 2.1 事件实体提取（LLM 直接推理，无需工具）

| 要素 | 定义 | 取值来源 |
|------|------|---------|
| **主体** | 公司名 / 产品名 / 技术名 / 政策名 | 事件描述 |
| **动作** | 量产 / 发布 / 限制 / 补贴 / 突破 / 制裁 | 事件描述 |
| **行业域** | 新能源 / 半导体 / 机器人 / AI / 消费电子 / 电力 / 商业航天 / 医药 / 军工 / 核聚变 等 | 依据主体归类 |

**`{事件关键词}` 生成规则**（全文占位符统一按此生成）：

1. 优先使用用户传入的 `event_keywords`；
2. 否则从事件描述中提取 **3-5 个**关键词：主体名、产品名、技术名、政策名；
3. **禁止**包含日期、数字、"利好/利空"等情绪词与判断词；
4. 关键词以空格分隔拼接后替换模板中的占位符。

**`{行业域}` 生成规则**：取上表"行业域"列的一个值；跨领域事件取 1-2 个主题名，用空格分隔。

### 2.2 产业链知识检索（RAG，本步骤最关键）

并行发起以下 4 组查询：

```yaml
# 查询组 A：产业链全景结构
query_chain_panorama:
  server_type: financial_docs
  tool: get_financial_news
  params:
    query: "{行业域} 产业链全景 上游 中游 下游 核心环节 价值量分布"

# 查询组 B：事件主体的供应链
query_subject_supply_chain:
  server_type: financial_docs
  tool: get_company_announcements
  params:
    query: "{事件主体} 供应链涉及的关键设备、零部件、原材料和耗材供应商"

# 查询组 C：传导逻辑与受益环节
query_transmission_logic:
  server_type: financial_docs
  tool: get_financial_news
  params:
    query: "{事件描述} 对产业链各环节的传导影响和受益分析"

# 查询组 D（仅境外事件必加，否则跳过）：海外供应链分析
query_overseas_chain:
  web_search:
    query: "{事件英文关键词} supply chain breakdown which segments benefit most"
```

**查询构造规范**见文末「查询构造规范」一章（本章不重复展开），提交前逐条核对。

**失败处理**：某组查询空返回 → 用同义措辞重试**最多一次**；仍失败 → 换 `web_search` 兜底；再失败 → 该组标注 `[数据暂不可用]` 并记入 `meta.降级说明[]`。

### 2.3 LLM 推理映射

**推理任务 1：节点提取**

从检索结果中提取所有被提及的产业链环节名称，去重后按标准层级归类：

```
上游原材料/耗材 → 上游核心零部件/设备 → 中游制造/集成 → 下游应用
```

- 跨层节点（如"设备+材料一体化"）归入**主要收入来源所在层级**，并在报告中注明跨层；
- 检索结果中未出现的环节名**不得新增**。

**推理任务 2：上下游关系构建**

对每个节点，从检索结果中推断：

- 该节点的上游是什么？（它需要采购什么）
- 该节点的下游是什么？（谁采购它的产品）
- 该节点在事件传导链中的位置？（第几级传导）

**推理任务 3：传导强度判定**

综合三个维度判定，**取最保守的结论**：

| 维度 | 高 | 中 | 低 |
|------|----|----|----|
| ① 传导直接性 | 直接拉动/压缩该环节需求（一级传导） | 经 1 跳传导 | 弱相关或仅概念关联 |
| ② 价值量占比 | ≥10% | 3%~10% | <3% |
| ③ 验证信号 | 有明确订单、客户定点、招标、价格变化等佐证 | 有部分佐证（机构测算、行业数据） | 无佐证 |

**口径定义**：`价值量占比` = 该环节在**本事件所涉整机/BOM 成本或终端收入**中的占比。同一输出内口径必须统一，并在报告"分析口径"中注明采用哪一种。

**判定规则**：

1. **高** = ①为高 **且** ③为高（②作为加权参考，不单独定档）；
2. **中** = ①或③为"中"，且不满足"高"；或 ①为高但 ③偏低；
3. **低** = ①为低，或仅为概念关联；
4. ②的阈值边界统一为 `≥10%` / `3%~10%` / `<3%`（不出现两档重叠的写法）；
5. **②不可获取时禁止套用数字档**：直接降为**低**，并在 `传导逻辑` 中标注 `[数据暂不可用]`；
6. 承压侧同样适用，表述为"事件直接压缩/间接压缩该环节需求"。

**推理任务 4：传导路径构建**

将节点按传导顺序排列，标注：

- **传导类型**：`一级传导`（直接受益/承压）/ `二级传导`（间接受益/承压）
- **传导逻辑**：一句话说明为什么受益/承压
- **关键验证点**：需要后续数据验证的核心假设

**推理任务 5：产业阶段判定**

将事件对该细分方向定性为以下五种之一：

| 产业阶段 | 定义 | 关键判据 | 典型信号词 |
|---------|------|---------|-----------|
| **概念炒作** | 事件驱动，无基本面支撑 | 政策口号、实验室成果、PPT 发布 | "宣布布局"、"战略合作"、"概念验证" |
| **技术突破** | 技术实质性进展 | 样机验证、中试线跑通、性能指标突破 | "样机测试"、"效率突破"、"送样测试" |
| **产业化拐点** | 技术成熟+需求爆发+产能扩张 | 量产计划明确、客户下单、设备招标 | "量产计划"、"客户定点"、"产线建设" |
| **量产前夕** | 产业链就绪，即将放量 | 产线调试完成、认证通过、产能爬坡 | "产线调试完成"、"批量交付"、"产能爬坡" |
| **需进一步跟踪** | 信息不足以判断 | 检索结果未覆盖关键判据 | —— |

判断决策树：

```
事件信息
├─ 有明确的下游客户订单？
│   ├─ YES → 已进入产能爬坡？
│   │         ├─ YES → 【量产前夕】
│   │         └─ NO  → 【产业化拐点】
│   └─ NO  → 有样机/中试线/性能验证数据？
│              ├─ YES → 【技术突破】
│              └─ NO  → 【概念炒作】
└─ 信息不足以判断 → 【需进一步跟踪】
```

**推理任务 6：两轴正交说明**

`影响定级` 与 `传导强度` 是**两个独立轴**，分别判定后再组合，禁止互相推导：

| 轴 | 描述 | 作用域 | 可选值 |
|----|------|--------|--------|
| 影响定级 | **事件本身的能量** | 全局（每个方向标注，但由事件决定） | S / A / B / C |
| 传导强度 | **该环节受传导的远近与弹性** | 每个环节 | 一级传导 / 二级传导 + 高 / 中 / 低 |

合法组合示例：`影响定级: A` + `传导强度: 一级传导/高`；`影响定级: A` + `传导强度: 二级传导/中`。
非法做法：因事件为 A 级就把二级传导环节写成"高"，或把低强度环节升格为 S 级。

**事件级字段落位规则**：

## Step 3：风险评估与证伪点分析

### 目标

识别分析逻辑的脆弱点，明确什么情况下逻辑会失效。

### 工具调用

**按 Step 2 已产出的细分方向分批查询**（每批次对应一个已知节点，禁止使用未知占位符）：

```yaml
query_industry_risk:
  server_type: financial_docs
  tool: get_financial_news
  params:
    query: "{细分行业} 面临的主要风险 竞争格局变化 技术路线不确定性"
```

### 分析要求

**证伪点数量**：

- 关键方向（`传导强度` 为高，或 `影响定级` ≥ B）→ **2-3 条**证伪点
- 其余方向 → **1-2 条**
- **全篇证伪点总数 ≤ 12 条**；超出时按 `影响定级` 与 `传导强度` 排序保留最重要的

**每条证伪点必须包含**：

| 字段 | 要求 |
|------|------|
| 证伪条件 | 什么情况发生意味着逻辑失效（≤60 字） |
| 发生概率 | 高/中/低，基于检索结果判断 |
| 影响程度 | 高/中/低 |
| 跟踪指标 | 如何监测该条件是否发生。**必须落到可观测口径**：指标名（如 EDB 指标名、产品价格、订单/招标公告、认证节点）或披露口径（如定期报告披露项） |
| 证据来源 | `Wind 金融终端` / `公司公告` / `新闻搜索` / `互联网查询` / `券商研报` 之一；无来源写 `[数据暂不可用]` |

**禁止**：`跟踪指标` 写"持续观察""密切关注""留意后续"等不可执行表述；`发生概率` 凭空给出数字百分比。

区分**短期情绪风险**（1 周-6 个月）与**长期基本面风险**（6 个月以上），并在报告中分别归类。

```
□ 传导强度是否按"直接性 + 价值量占比 + 验证信号"取最保守结论？价值量占比不可得时是否降为低并标注 [数据暂不可用]？
□ 影响定级与传导强度是否作为两个独立轴分开判定（未互相推导）？
□ 产业阶段是否取自五值枚举（含「需进一步跟踪」）？
□ 是否区分一级传导与二级传导？
□ 所有数据是否标注来源与时点？事件日期是否来自检索结果（未获得是否写"未标注"而非推算）？
□ 每个关键方向是否含 2-3 条证伪点（全篇 ≤12 条），且含证伪条件/发生概率/影响程度/跟踪指标/证据来源？
□ 跟踪指标是否落到可观测口径（无"持续观察"类表述）？
□ 推理置信度是否标注？低置信度节点是否标为"待验证"？
□ 是否遵守篇幅控制（环节 ≤12、证伪点 ≤12、报告 ≈1200 字、各字段字数上限）？
□ 是否遵守格式规范（数据不虚构）？
□ 输出中是否**完全没有**个股名称/代码/标的清单？
□ 结论是否先行、逻辑是否闭环？
□ 写文件时：路径是否为用户指定或默认 event-chain-output/？是否未写技能自身目录？是否如实报告路径与覆盖？写入失败是否未谎报？
```

## 查询构造规范

### financial_docs 查询规则（RAG 检索核心）

RAG 是语义向量相似度匹配，不是关键词搜索。查询语句语义越贴近目标文档的实际表述，召回质量越高。

**四条规则**（每条查询提交前逐一核对）：

1. **长度控制在 15-30 字**：过长稀释语义权重
2. **一条查询一个分析维度**：多维度拆成多条并行
3. **模拟文档原文措辞**：使用自然语句，不是关键词堆砌
4. **禁止使用抽象框架词**：

| 禁止使用 | 替换为 |
|---------|--------|
| 护城河可持续性 | 技术壁垒与竞争对手对比 |
| 核心竞争优势 | 差异化优势与市场份额 |
| 行业景气度变化 | 市场规模、增速与渗透率 |
| 未来催化剂 | 新产品发布、客户拓展计划 |

### 查询模板占位符对照

| 占位符 | 生成规则 | 使用位置 |
|--------|---------|---------|
| `{事件关键词}` | Step 2.1（3-5 个，不含日期与情绪词） | Step 1 查询 1/2 |
| `{事件描述}` | 用户的 `event_description` 原文 | Step 2 查询组 C |
| `{事件主体}` | Step 2.1 的"主体" | Step 2 查询组 B |
| `{行业域}` | Step 2.1 的"行业域"（1-2 个） | Step 2 查询组 A |
| `{细分行业}` | Step 2 产出的节点名，**按节点分批填充** | Step 3（仅对已知节点查询） |
| `{事件英文关键词}` | `{事件关键词}` 的英文对应 | Step 1 查询 3、Step 2 查询组 D（仅境外事件） |

### Fallback 策略

```
financial_docs 无结果 → 同义措辞重试一次 → web_search 补充 → 标注 [数据暂不可用] + 记入 meta.降级说明
web_search 无结果 → 标注 [数据暂不可用] + 记入 meta.降级说明
Wind MCP 未就绪/W4 失败 → 输出「Wind 未就绪提示语」→ 用户确认后仅用 web_search
```

> ⚠️ **绝对禁止**：任何层级的 fallback 耗尽后，禁止虚构数字、指标、事件日期、环节名称或来源标注。只能标注缺失，并说明对分析判断的影响。

## RAG 检索 + LLM 推理的优势与局限

### 优势

- **零预建成本**：不需要维护产业链知识图谱，即装即用
- **覆盖面广**：理论上可分析任意产业链，包括新兴概念（如"具身智能"、"AI Agent"）
- **基于最新检索**：每次基于本次检索到的研报和新闻，能反映产业链的最新表述
- **交叉产业链友好**：多链融合场景下，可同时检索多个领域的研报

### 局限

- **RAG 检索质量依赖**：若相关研报少（冷门产业链），推理质量下降
- **LLM 幻觉风险**：检索结果不足时，LLM 可能"脑补"产业链关系
- **一致性较弱**：同一事件多次分析，结果可能有差异
- **速度较慢**：每次需要 4 组 RAG 查询 + LLM 推理

### 缓解措施

- Step 2 的 4 组查询覆盖多个角度，降低单一查询失败的影响
- 输出中标注 `推理置信度`（高/中/低），低置信度节点在报告中标为"待验证"
- 关键结论必须有检索结果支撑，禁止凭空推断
- 全篇证伪点与环节数受篇幅控制规范限制，避免低置信度内容稀释结论
