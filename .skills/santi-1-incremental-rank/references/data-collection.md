### 1.2 调用前必读

- `wind-mcp-skill` 的参数名、枚举、必填项一律**回其 `references/<领域>.md` 取**，不凭记忆填。
- `get_stock_price_indicators` 的 `indexes` 字段逐字复制 wind-mcp-skill `references/stock-indicators.md`；表内没有的字段不得猜测。
- `economic_data` 的 `executionMode=搜索并提数` 时**必须**显式给 `beginDate`/`endDate` 或 `observation`（与 question 中的时间描述不互斥）；不得仅把时间范围写进 `question`。
- 批量调用默认**串行**（并发 1）：同一 `server_type + tool_name` 先发一个探针，探针成功才继续其余；探针失败立即终止该批次。

### 1.3 市值口径（硬性）

- 本技能固定使用 **`总市值2`（含限售股）**，写入 `龙头股[].mcap.index_field`。
- 不混用 `总市值1`；不得输出未声明口径的"总市值"。
- 市值单位统一为**亿元**，`mcap.value` 保留 Wind 返回的精度。

## 2. 三条硬约束（强制）

### 硬约束 1：双查询法（趋势判断强制触发）

市场规模维度**必须**成对执行，缺一不可：

```
查询A（当前状态）："{方向}行业截至最新年度的市场规模、营业收入同比增速"
查询B（历史序列）："{方向}行业近5年的市场规模、营业收入同比增速历史数据"
```

- 两条**禁止合并**为一条；合并后写 `dual_query.merged = false` → 校验失败（`E_DUAL_QUERY_MISSING`）。
- 查询 A 的用途：拿到最新值；查询 B 的用途：算 CAGR、定趋势方向。只查历史会漏最新值，只查最新值算不出 CAGR。
- `dual_query.current` / `dual_query.history` 记录该条查询是否**实际发出并拿到回执**（空结果也算"已发出"，但须记入 `降级说明[]`）。

### 硬约束 2：时间范围四写法（禁止裸查询）

| 场景 | 标准写法 | 对应字段 |
|------|---------|---------|
| 最新值 | `截至最新年度的…` | `市场规模.current` |
| 历史序列 | `近5年的…历史数据` | `市场规模.history` |
| 特定区间 | `2020-2025年的…` | 历史序列或区间对比 |
| 特定报告期 | `2025年全年的…` | 单年值或年报口径 |

- **禁止**裸查询：`"XX行业的市场规模"` 这类无时间状语写法一律不合格。
- **取数后回填具体年份**：把查询/结果中的"最新年度"落实为具体年份（如 `截至2025年度`），并同步写入 `meta.查询对象.截至年度`。若始终无法确定年份，`source.year` 写 `未标注`，置信度按 §4 降级为**低**。
- 违规判定：`data-collection` 自检项 R2；`SKILL.md` 自检清单单列一条。

### 硬约束 3：单条查询 ≤ 6 指标 + 排名条件内嵌

- 单条查询涉及指标数 `≤ 6`（模板库每条已标注指标数）。
- **排名/筛选条件必须写进自然语言**，一次返回目标集合：
  - ✅ `"XX行业按营业收入降序前10名公司及其营业收入、营业收入同比增速"`
  - ❌ 先查"全行业公司列表"，再本地筛选
- 长度：**建议 15–30 字**以保 RAG 召回质量；含排名条件时放宽，但不得堆砌无关维度（一条查询只承担一个分析维度）。
- 抽象框架词禁止：`行业景气度变化` → 换成 `市场规模、增速与渗透率`；`未来催化剂` → 换成 `新产品发布、客户拓展计划`。

| Q-C | `{方向}行业截至{年}的渗透率及近3年的渗透率变化趋势` | #4 | 2 | 最新值 |

## 4. 来源与置信度判定

### 4.1 来源枚举（逐字使用）

| `source.type` | 适用场景 |
|--------------|---------|
| `Wind 结构化数据` | Wind 行情、财务、估值、宏观/行业 EDB 指标 |
| `公司公告` | 公告、定期报告、招股书 |
| `Wind 新闻检索` | Wind 财经新闻检索结果（`financial_docs.get_financial_news`） |
| `券商研报` | 券商研究报告观点与数据 |
| `互联网查询` | 通用互联网信息（含第三方机构测算） |

### 4.2 三维修正（取**最保守**结论）

| 维度 | 高 | 中 | 低 |
|------|----|----|----|
| 来源权威性 | `Wind 结构化数据` / `Wind 新闻检索` | `公司公告` / `券商研报` | 第三方机构测算 / 互联网查询 |
| 口径匹配 | 与目标口径一致 | 需单位/汇率换算但口径一致 | 口径偏大或偏小 |
| 时效 | ≤1 年 | 1–2 年 | >2 年或年份不明（`未标注`） |

- 最终 `confidence ∈ {高, 中, 低}`，并把三维修正过程写入 `confidence_basis`（一行，可核对）。
- **一致性校验（机械规则）**：`source.type ∈ {互联网查询}` 或 `source.detail` 含第三方机构名（QYResearch、TrendForce、弗若斯特沙利文、IDC、GGII 等）时，`confidence` **不得为「高」**；违反 → 自动降为「中」，记 `W_CONFIDENCE_UPGRADED` 并追加到备注。

### 4.3 口径降级三条件（脚本强制，缺一即校验失败）

当精确口径查不到、改用近似口径替代时，必须同时满足：

1. **显式声明口径差异**：`precision = "近似"`，`caliber` 写明实际口径；禁止把近似当精确用。
2. **说明偏大还是偏小**：`caliber_vs_target ∈ {偏大, 偏小}`（这是评分置信度的关键输入）。例：目标"卫星数据中台与 AI 服务"查不到 → 命中"全球太空算力 $1,689亿"，该口径覆盖硬件+软件+服务全产业链，远大于目标口径，必须写 `caliber_vs_target: "偏大"`，并在 `caliber_note` 注明"该口径不能作为目标环节的精确值"。
3. **标注来源与年份**：`source.detail` 写清机构名与测算年份，且 `tag = "[待验证]"`（第三方测算一律 `[待验证]`，不得标 `[已证实]`）。

### 4.4 汇率与单位换算边界

- `config.units` 为每类金额显式声明 `unit`（`亿元`/`亿美元`/`万亿元`/`万元`）与 `currency`（`CNY`/`USD`）。
- **内部统一换算为人民币亿元**，换算过程**显式写出**并留痕到 `meta.单位与汇率`，禁止心算。
- 汇率优先级：① 用户指定值 → ② Wind 最新汇率（`economic_data`，来源写 `Wind 结构化数据`）。两者都取不到时不得换算，该要素置信度降为**低**并记 `W_FX_ASSUMED`/降级说明。
- 万亿 × 10000 = 亿；万美元 ÷ 10000 = 亿美元；`亿美元 × fx.usdcny ÷ 1 = 亿元`（保留小数，不提前取整）。

### 4.5 Fallback 顺序

```
financial_docs / economic_data 无结果 → 同义措辞重试一次 → web_search 补充
web_search 无结果 → 标 [数据暂不可用] + 记入 meta.降级说明[]
wind-mcp-skill 未就绪 → 输出「未就绪提示语」→ 用户确认后才允许仅用 web_search
```

**禁止**：任何层级的 fallback 耗尽后虚构数字、机构名、年份或来源标注；只能标注缺失，并说明对结论的影响。

## 5. 取数自检（逐条核对，全过才进 Step 4）

```
□ R1 每个细分方向的市场规模是否都执行了查询 A + 查询 B 两条（未合并）？
□ R2 每条查询是否都带四种时间写法之一（无裸查询）？
□ R3 每条查询指标数是否 ≤6？排名/筛选条件是否内嵌在自然语言里（未先取全列表再本地筛）？
□ R4 每个数据点是否都有 source.type 与 confidence？置信度是否 ∈ {高,中,低}？
□ R5 第三方机构/互联网查询的数据点是否未标「高」置信度？
□ R6 近似口径是否声明了 caliber、caliber_vs_target（偏大/偏小）、source.detail（机构+年份）与 [待验证]？
□ R7 单位与汇率是否显式声明、换算过程是否留痕（无心算）？
□ R8 市值口径是否固定「总市值2」，且龙头股是否按市值排序取前 3？
□ R9 取数失败项是否如实标 [数据暂不可用] 并记入 meta.降级说明（未编造）？
□ R10 未被 Wind 覆盖的要素是否走了 web_search 并标注来源与置信度？
```
